# v0.60 / Shell Structured Argument Provenance Shell 结构化参数来源

提交信息：`v0.60: 阻断 Shell 顶层命令别名`

## 版本分配依据

v0.59 已阻断同名 executable 路径绕过，但 Gateway 的 `structuredShellCommand()` 仍接受 action 顶层 `shellCommand` 和 `commandLine`。Swift schema、planner 与协议只定义 `toolArguments.shellCommand`，因此未知顶层字段可能绕过上游对 `toolArguments` 的审批与审计，并被错误标记为 `structured-arguments-only`。本轮收紧命令来源并提供可审计的固定阻断诊断。

## 目标

- `runShellCommand` 只允许字符串型 `action.toolArguments.shellCommand` 成为命令来源。
- action 顶层 `shellCommand` 或 `commandLine` 任一存在时 fail closed，包括与合法嵌套命令并存的歧义情况。
- 阻断发生在 parse、binary allowlist 和 `runProcess()` 前，仅失败当前 action，保留其他 action 与 session 审计。
- 新增固定 mode/diagnostic `invalid-structured-command-source`，retry reason 复用 `provide-structured-command`。
- metadata 和 UI 明确显示非法来源已阻断，且不暴露 alias 值、命令或 marker。

## 非目标

- 不全局拒绝所有未知 envelope/action 字段，不升级 schema。
- 不改变合法 `toolArguments.shellCommand`、Shell executable allowlist 或审批策略。
- 不新增 action/event/artifact kind，不实现自然语言 Shell、完整路径 allowlist 或命令模板。
- 不处理 Browser redirect、Mission Run session affinity 或其他后续候选。
- 不修改用户已有 Xcode 工程和 scheme 改动。

## 当前架构依据

- `Tools/claw-gateway-server.mjs` 的 `structuredShellCommand()` 当前依次回退到嵌套字段、顶层 `shellCommand`、顶层 `commandLine`。
- `runShellAction()` 是 action-bound 安全失败和 Shell Safety artifact 的正确边界；不应在 `validateEnvelope()` 阶段无审计终止整个 envelope。
- `ClawMobileAction` 与 `PhoneAgentPlanner` 只编码 `toolArguments.shellCommand`，合法 iPhone/iPad 客户端无需迁移。
- `ClawGatewayShellCommandSafetyReviewSummary` 已 allowlist Shell mode/diagnostic/safety flags，可扩展固定枚举并继续使用现有 UI。

## 实现步骤

1. 增加顶层 Shell alias presence 检查，任一字段存在即在 `runShellAction()` 开头写固定、无命令内容的阻断 artifact，并返回 retryable action failure。
2. 将 `structuredShellCommand()` 收紧为只读取 `toolArguments.shellCommand`。
3. `shellPolicyDiagnostics()` 增加 `invalid-structured-command-source`；`shellCommandSafetyMetadata()` 增加 `invalid-command-source-blocked` safety flag。
4. 阻断 metadata 必须为 `commandParsed=false`、`binaryAllowlistChecked=false`、`allowlistMatched=false`、`executionAttempted=false`、`executed=false`；`structuredCommandPresent` 只反映合法嵌套字段是否存在，不代表执行。
5. Swift review parser、复核需求派生和 SwiftUI icon/tint 接受并展示新固定诊断与 safety flag。
6. direct smoke 分别覆盖顶层 `shellCommand`、顶层 `commandLine`、合法嵌套字段与冲突 alias 并存；使用可执行 canary/marker 证明没有执行，并检查 artifact payload 与事件均不泄露 alias 值。
7. WebSocket smoke 至少覆盖 alias-only 真执行条件，断言 action failure、无副作用、无命令泄露和完整 metadata。
8. XCTest/LogicSmoke 覆盖新诊断解析、policy review 与敏感值拒绝；保留合法 Swift 编码和 v0.59 回归。
9. 同步 README、协议、flow/flowchart、test 与 update_log。

## 验收标准

- 顶层 `shellCommand`、`commandLine` 均不能驱动执行。
- 合法嵌套命令与任一顶层 alias 并存时 fail closed，不选择其中任一命令。
- 正常 `toolArguments.shellCommand=pwd` 仍能通过 allowlist 真执行。
- alias 阻断事件、metadata 和 artifact payload 不包含 alias 命令或 canary，marker 不存在。
- 手机端能解析并显示固定来源阻断诊断，且 `requiresShellPolicyReview=true`。
- 最新 `origin/main` CI artifact 与本轮 commit/run/attempt 完全一致并全部通过。

## 风险和禁止项

- 风险：只删除 fallback 而没有冲突检测，会在合法嵌套命令与恶意 alias 并存时继续执行；必须 fail closed。
- 风险：在全局 envelope validation 拒绝会丢失 action-bound 审计并扩大兼容性影响；本轮不得这样实现。
- 风险：阻断 artifact 若写入 alias 原文会形成敏感数据残留；payload 必须使用固定文案。
- 禁止本地编译或 smoke、删除断言、放宽 allowlist、输出 raw command/path/stdout/stderr/token/header/`toolArguments`，或混入 Xcode 用户改动。
