# v0.61 / Browser Redirect Host Allowlist 浏览器重定向逐跳白名单

提交信息：`v0.61: 阻断浏览器重定向越权`

## 版本分配依据

v0.48 已为 Browser Control 增加固定策略诊断，但 Gateway 网络抓取仍使用 `fetch(..., redirect: "follow")`。当前只检查初始 URL host，允许的站点可把请求重定向到未授权 host，Node 会在 Gateway 再次检查前自动发出请求。本轮修复这一跨 host 重定向边界，并把结果作为脱敏、可复核的固定 metadata 回传手机和 iPad。

## 目标

- 浏览器网络抓取改为手动重定向，每一跳在发出请求前重新检查协议和 host allowlist。
- 只允许 `http:`/`https:`，支持相对 `Location`，最多跟随 5 次重定向，并在整个链路共享一个总超时。
- 未授权 host、非法协议、URL credentials、缺失/非法 Location 和超过跳转上限均 fail closed，目标端点不得被访问；失败必须绑定当前 action 并保留脱敏 Browser artifact。
- Browser Control metadata 增加固定、脱敏的重定向策略证据，手机/iPad 能区分已检查、已阻断和超过上限。
- direct 与 WebSocket 云端 smoke 使用小型本地 HTTP server 证明同 host 相对跳转成功、跨 host 跳转零访问并覆盖上限边界。

## 非目标

- 不实现点击、表单填写、登录态、cookie jar、下载器、代理、DNS/IP 分类或完整 SSRF 防护。
- 不改变 envelope schema、action/event/artifact kind、桌面浏览器 AppleScript 策略或最终提交闸门。
- 不把 URL、host、Location、header、cookie、页面正文或 redirect 链写入 metadata/UI。
- 不处理 Mission Run session affinity、Agent Loop allowlist 交集或其他后续候选。
- 不修改用户已有 Xcode 工程和 scheme 改动。

## 当前架构依据

- `resolveBrowserInput()` 已校验初始 URL protocol、`CLAW_ALLOW_BROWSER_NETWORK` 和 `CLAW_BROWSER_HOST_ALLOWLIST`。
- `fetchWithTimeout()` 当前使用 `redirect: "follow"`，自动跳转绕过逐跳检查。
- `browserControlReviewMetadata()` 是 `browserTrace` 与 browser-control artifact 共用的 metadata-only 审计边界。
- `ClawGatewayBrowserControlReviewSummary` 和现有 SwiftUI Browser Control row 已支持向后兼容解析固定 metadata。

## 实现步骤

1. 将网络 fetch 改为 `redirect: "manual"` 循环，保留一个 `AbortController` 和一个总计时器。
2. 每次 fetch 前解析当前 URL，确认 protocol 为 HTTP(S)、hostname 在既有 allowlist；使用 `new URL(location, currentURL)` 解析相对跳转。
3. 只把 301、302、303、307、308 视为跳转；credentials、缺失或非法 `Location`、协议阻断、host 阻断、超过 5 次均返回固定阻断结果，不联系下一目标。
4. `resolveBrowserInput()` 消费结构化 fetch 结果：成功为 `network-fetch`，策略阻断为 `network-blocked`，并携带仅含计数/布尔/固定枚举的 redirect evidence；`controlBrowserAction()` 为阻断写 action-bound Browser artifact 并返回失败，不能冒泡成 session 级通用错误。
5. Browser Control metadata 增加 `redirectPolicyChecked`、`redirectCount`、`redirectBlocked`、`redirectLimitExceeded` 和固定 `networkPolicyDiagnostic`；safety flags 增加逐跳策略检查/阻断证据。所有字段保持字符串化和向后兼容。
6. Swift review parser allowlist 新枚举/flag，`requiresPolicyReview` 和 compact status/UI row 对阻断或上限结果明确提示；敏感或未知值必须拒绝或降级。
7. direct smoke 启动最小 HTTP server，覆盖同 host 相对 redirect 成功、`127.0.0.1` 到 `localhost` 越权阻断且目标 hit count 为 0、跳转上限阻断，以及 metadata key/枚举/脱敏断言。
8. WebSocket smoke 至少覆盖跨 host 越权阻断与目标零访问，并验证事件闭环和 metadata 不泄露 URL/host/Location。
9. XCTest 与 LogicSmoke 覆盖新字段解析、阻断触发 policy review、compact/UI 派生和敏感值拒绝。
10. 同步 README、协议、flow/flowchart、test 与 update_log。

## 验收标准

- 初始 host 与每个 redirect host 都在发请求前经过同一 allowlist 检查。
- 同 host 相对跳转可成功获取最终 HTML；跨 host 跳转被阻断且目标 server hit count 为 0。
- 超过 5 次跳转 fail closed，不进入无限循环；整个链路使用一个总超时。
- redirect 策略失败只失败当前 action，同一 session 后续 action 仍可继续。
- browser artifact metadata 只包含固定枚举、布尔和有限计数，手机/iPad 能明确显示 redirect policy 状态。
- metadata、事件和 UI 不包含 raw URL、host、Location、header、cookie、页面正文、token 或 `toolArguments`。
- 最新 `origin/main` CI artifact 与本轮 commit/run/attempt 完全一致并全部通过。

## 风险和禁止项

- 风险：先 fetch 再检查最终 `response.url` 仍会联系未授权目标，不能作为修复。
- 风险：每跳重建 timeout 会让攻击者无限延长总耗时，必须共享总截止时间。
- 风险：用 host 字符串后缀或 URL 文本匹配会产生边界绕过，必须使用 URL parser 和精确 hostname allowlist。
- 风险：测试若只断言最终失败，无法证明目标未访问；必须记录目标 hit count。
- 风险：Gateway fetch 的逐跳检查不等于控制桌面浏览器后续导航；文档不得声称 AppleScript 打开后的重定向已受控。
- 禁止本地编译或 smoke、删除断言、放宽 allowlist、输出 redirect 链或敏感 payload，或混入 Xcode 用户改动。
