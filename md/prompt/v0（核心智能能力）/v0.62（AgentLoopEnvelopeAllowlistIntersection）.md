# v0.62 / Agent Loop Envelope Allowlist Intersection 智能体下一步白名单交集

提交信息：`v0.62: 收紧 Agent Loop 推荐动作白名单`

## 版本分配依据

v0.61 已通过最新 `origin/main` 云端 artifact 验收。当前 `runAgentLoop` 仅使用 action 自身的 `toolArguments.allowedNextActions` 过滤建议，没有与 envelope 的 `gateway.allowedActionKinds` 取交集；同时 `proposeAgentNextActions()` 把空 allowlist 当成“允许全部”。恶意或过期客户端因此可让 `agentTrace` 推荐 envelope 明确未授权的动作，误导手机/iPad 人工继续循环。

## 目标

- Agent Loop 有效下一步集合必须是结构化 `allowedNextActions`、envelope `allowedActionKinds` 与 Gateway 固定支持推荐种类的精确三方交集。
- 固定支持推荐种类仅为 `observeScreen`、`controlBrowser`、`manageFiles`、`extractData`、`operateDesktopApp` 和 `composeMessage`；`runShellCommand`、`composeEmail`、`runAgentLoop` 与未知 kind 不可作为推荐。
- 空交集 fail closed，只生成固定 `none` 建议，不回退为全部动作。
- `nextActions`、`selectedNextAction`、iterations、safety gates、handoff 和 metadata 都只能基于有效集合派生。
- metadata 增加固定、脱敏的交集策略证据，手机/iPad 能显示请求数、有效数、阻断数和 selected action 是否受 envelope 授权。
- direct/WebSocket 云端 smoke 证明未授权建议不会出现在 artifact、metadata 或 handoff 中。

## 非目标

- 不自动执行 Agent Loop 建议，不新增多轮执行器、调度队列或 action kind。
- 不把自然语言转成 Shell、AppleScript、浏览器或桌面动作。
- 不改变 envelope schema、审批规则、真实 action handler allowlist 或 artifact/event kind。
- 不展示完整 allowlist、自然语言 reason/instruction、artifact payload、token/header 或 `toolArguments`。
- 不修改用户已有 Xcode 工程和 scheme 改动。

## 当前架构依据

- `buildGatewayEvents()` 可从已验证 envelope 取得 `gateway.allowedActionKinds`，但当前 `sessionConfig` 未携带该集合。
- `agentLoopAction()` 解析 `allowedNextActions` 后直接调用 `proposeAgentNextActions()`。
- `proposeAgentNextActions()` 当前使用 `allowlist.length === 0 || allowlist.includes(kind)`，空集合会 fail open。
- `agentTraceMetadata()` 与 `ClawAgentTraceReviewSummary` 已是 Agent Loop 的 metadata-only 手机/iPad 复核边界。

## 实现步骤

1. `buildGatewayEvents()` 把 envelope `allowedActionKinds` 的规范化精确集合只作为当前 session 的内部策略上下文传给 handler。
2. `agentLoopAction()` 分开保存 requested next actions 和 effective next actions；有效集合按 `dedupe(requested) ∩ envelope allowed ∩ fixed supported recommendation kinds` 计算并保持请求顺序。
3. `proposeAgentNextActions()` 改为严格 includes；空集合只追加固定 `none`，不得建议任何可执行动作。
4. trace 保留 `allowedNextActions` 表示有效集合，可新增 requested/effective/blocked 计数和固定 `nextActionPolicy=envelope-intersection`，但不在 metadata 中暴露完整列表。
5. metadata 增加 `nextActionPolicy`、`requestedNextActionCount`、`effectiveNextActionCount`、`blockedNextActionCount`、`selectedNextActionAllowedByEnvelope`；`none` 视为安全停止状态。
6. Swift parser 对 policy 使用固定 allowlist、计数使用有限非负范围；未知 policy 或 selected action 未获授权时 fail closed 进入人工复核。UI 用紧凑 chip 展示交集策略和计数，不显示 raw allowlist。
7. direct smoke 覆盖请求仅含 envelope 外动作、部分交集和空交集；断言 artifact 内 `nextActions/selectedNextAction/iterations/safetyGates` 无越权 action，metadata 不泄露列表。
8. WebSocket smoke 至少覆盖 envelope 仅允许 `runAgentLoop`、action 请求 `operateDesktopApp,composeMessage`，结果必须 selected `none`、effective count 0、blocked count 2，并完成 session。
9. XCTest/LogicSmoke 覆盖新字段、unknown policy fail closed、selected action 未授权状态和敏感值拒绝。
10. 同步 README、协议、flow/flowchart、test 与 update_log。

## 验收标准

- 任何 `agentTrace` 可执行建议都同时存在于 requested next actions 和 envelope allowlist。
- 空交集只产生 `kind=none`，selected action、iteration proposal 和 handoff 不包含 envelope 外动作。
- metadata 只包含固定 policy、有限计数和布尔证据，未知/矛盾状态在手机/iPad fail closed。
- 双 smoke 明确断言越权 action 不出现在 artifact/metadata/event，且 session 正常完成。
- 最新 `origin/main` CI artifact 与本轮 commit/run/attempt 完全一致并全部通过。

## 风险和禁止项

- 风险：先取交集再继续使用“空列表表示全部”的旧 helper 仍会 fail open，必须同时收紧 helper 语义。
- 风险：只过滤 `selectedNextAction` 而保留越权 `nextActions`、iterations 或 safety gates 会继续误导复核，所有派生必须来自有效集合。
- 风险：把完整 allowlist 写入 metadata/UI 会扩大策略信息暴露，只允许计数和固定布尔。
- 禁止本地编译或 smoke、删除断言、伪造 Agent C 通过、输出原始 allowlist/自然语言/payload，或混入 Xcode 用户改动。
