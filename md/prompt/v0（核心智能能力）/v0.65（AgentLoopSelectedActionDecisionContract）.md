# v0.65 / Agent Loop Selected Action Decision Contract 智能体选中动作决策契约

提交信息：`v0.65: 固化 Agent Loop 选中动作决策`

## 版本分配依据

v0.64 已由 Agent C 对最新 `origin/main` run `30195238561` 的 artifact 复判通过。v0.62 已把推荐限制在 request、envelope 和 Gateway 固定支持种类的三方交集，但 `selectedNextAction` 仍只有 kind、审批布尔和 envelope 授权布尔等松散 metadata。手机端无法证明它按固定算法来自候选集合；审批字段缺失时还会被折算为不需审批，可能错误显示 Loop 可继续。

## 目标

- 为 `runAgentLoop` 增加版本化、结构化、可审计的 selected-action decision contract。
- 固定选择策略为 `evidence-first-safe-v1`，用固定 reason 描述策略分支，不解析自然语言 reason。
- trace 和 metadata 记录候选数量、1-based 候选序位、是否来自候选集合及决策一致性。
- 明确区分三方交集为空的 `policy-blocked` 与上下文无需动作的 `no-action-needed`。
- Swift 对合同字段缺失、未知、越界或组合矛盾统一 fail closed，禁止 Loop 继续并要求人工复核。
- simulator、Swift fixture、direct/WebSocket smoke、XCTest、LogicSmoke 与协议文档保持一致。

## 非目标

- 不自动执行推荐，不新增真实多轮调度器、action/event/artifact kind 或 envelope 字段。
- 不把 metadata 当执行授权，不绕过 action policy、审批、workspace 或固定 handler gate。
- 不把自然语言 instruction/reason、完整 allowlist、`toolArguments`、URL/path/command、正文、token/header 或 artifact payload 写入 metadata/UI。
- 不处理完整 macOS Accessibility bridge、Playwright/browser-use 或后台保活。
- 不修改或提交用户已有 Xcode 工程与 scheme 改动。

## 当前架构依据

- `agentLoopAction()` 已计算三方交集并由 `proposeAgentNextActions()` 生成最多 6 个候选。
- `selectAgentNextAction()` 当前有证据恢复、首个免审批和首项回退分支，但不返回分支证据或候选序位。
- `ClawAgentTraceReviewSummary.requiresNextActionPolicyReview` 只校验交集 metadata；`selectedNextActionRequiresApproval == nil` 在 Loop 派生时被当作 `false`。
- Next Step Deck、Continuation Gate 等展示层继续消费 `loopContinuationSummary`，因此只需让该摘要依赖有效决策合同，无需新增执行入口。

## 实现步骤

1. 将选择函数改为返回 selected action 和结构化 decision；合同字段至少包含 policy、固定 reason、candidate count、1-based ordinal、from-candidates 和 consistent。
2. policy 固定为 `evidence-first-safe-v1`；reason 仅允许 `policy-blocked`、`no-action-needed`、`evidence-recovery`、`insufficient-evidence-fallback`、`safe-without-approval`、`approval-required-fallback`。
3. 三方交集为空时 selected 必须是 `none`、reason `policy-blocked`、effective count 0、stop `policy-blocked`、handoff `blocked`。
4. 有效集合非空但没有上下文候选时 selected 为 `none`、reason `no-action-needed`，进入 complete，不可继续。
5. 证据不足时优先候选中的 observeScreen/controlBrowser，否则首项回退；证据充分时优先首个不需审批候选，否则首项审批回退。ordinal 必须精确指向候选。
6. metadata 新增固定安全字段：`selectedActionDecisionPolicy`、`selectedActionDecisionReason`、`selectedActionCandidateCount`、`selectedActionCandidateOrdinal`、`selectedActionFromCandidates`、`selectedActionDecisionConsistent`。
7. Swift parser 使用固定枚举和有限整数；新增单一决策合同有效性/诊断派生。缺失、未知、ordinal 越界、kind/reason/approval/handoff/stop/policy 组合矛盾、from-candidates 或 consistent 非 true 都进入人工复核。
8. Loop `canContinue` 必须要求审批字段明确为 false 且完整决策合同有效；任何 nil 不得 fail open。UI 只显示固定决策 reason/状态，不显示自然语言或 payload。
9. 对齐 `ClawStore` simulator 和 `ClawGatewayEventFixture` metadata；不得继续固定输出与 Node 选择算法矛盾的证据。
10. direct/WebSocket smoke 覆盖 policy-blocked、no-action、证据恢复、免审批优先、全审批回退、ordinal/count 和 metadata 对称；Swift 回归覆盖字段缺失、未知、越界、false、组合矛盾和敏感 marker。
11. 同步 README、协议、flow、flowchart、test 和 update log。

## 验收标准

- 每个 selected action 都有固定策略分支、候选数量和准确序位；非 `none` 必须来自有效候选。
- policy-blocked 与 no-action-needed 的 stop/handoff 语义可区分且组合自洽。
- Swift 对任何缺失、未知、越界或矛盾合同都 `canContinueLoop=false`、`requiresHumanAction=true`、`hasMetadataGap=true`。
- 合法 `ready-to-continue` 只能是非 `none`、明确无需审批、交集 policy 合法且决策合同完整一致。
- metadata/UI 不泄露完整 allowlist、自然语言、payload 或敏感 marker；推荐仍是 advisory。
- 最新 `origin/main` CI artifact 与本轮 commit/run/attempt 完全一致并全部通过。

## 风险和禁止项

- 风险：只增加字段而不纳入 Swift `canContinue` 会保留原 fail-open，必须把合同有效性作为继续前置条件。
- 风险：fixture/simulator 与 Node 选择分支漂移会制造错误预览证据，必须同步固定策略。
- 风险：用未选中候选的 risk/gate 改写 selected decision 会造成决策语义污染；selected 合同必须描述实际选中项。
- 禁止本地编译或 smoke、删除测试断言、伪造 CI/Agent C 通过、自动执行建议、扩大权限或混入 Xcode 用户改动。
