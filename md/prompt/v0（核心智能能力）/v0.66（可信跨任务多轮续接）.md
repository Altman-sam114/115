# v0.66 / Trusted Cross-Task Multi-Round Continuation 可信跨任务多轮续接

提交信息：`v0.66: 实现可信跨任务多轮续接`

## 版本分配依据

v0.65 已在 `origin/main` commit `b375a5936bd5092a452d8166924fb006a4a1ce1e` 完成 selected-action decision contract，并由 Agent C 对 GitHub Actions run `30196781096` attempt `1` 的 artifact `claw-ci-v0.2-main-b375a5936bd5-run30196781096-attempt1` 复判通过。当前 `runAgentLoop` 已能用 `evidence-first-safe-v1` 区分 `safe-without-approval`、审批回退、证据恢复、policy blocked 和 no-action，但该 decision 仍是 metadata-only advisory：iOS 没有独立 continuation draft，Gateway 没有可验证的父 session receipt 或有界父 context，创建新 task 会丢失旧 session context，也没有真实的“执行 selected action 后再次运行 agent loop”多轮闭环。

因此本轮继续使用 v0 小版本，完成第一个受限但真实的跨 task 多轮续接能力。它不能把 v0.65 metadata 当授权，也不能退化成自动执行、复用旧 envelope 或在新 session 中伪造父证据。

## 背景与现状依据

- `ClawAgentTraceReviewSummary` 已解析 v0.65 decision metadata，并通过 `requiresNextActionPolicyReview` 对缺失、未知和矛盾合同 fail closed。
- `ClawStore` 当前通过 `clawMobileTasks.first` 生成、审批和发送最新任务；`approveAndContinueAutonomousLoop()` 会在同一次调用中审批并立即 dispatch，不适合 continuation draft。
- `missionRunResolution` 以最新 task 为根；直接把 continuation task 插到队首会立即切走父 Mission scope，使用户无法继续复核父 AgentTrace。
- `lastClawMobileEnvelope` 同时承担 UI 展示和 live transport body；异步期间被其他任务更新会产生错误 envelope 或敏感 lineage receipt 展示风险。
- `ClawMobileTask`、`ClawMobileEnvelope` 没有 continuation lineage、内容绑定审批记录或父 session provenance。
- Gateway 每次 `buildGatewayEvents()` 都创建新 session workspace 和空 `sessionContext`；新的 `extractData` task 无法可信消费父 session 的 browser/file/command/accessibility evidence。
- Gateway 已有进程内 task replay guard、固定 handler registry、action/envelope allowlist 和 token fingerprint 校验，可作为 receipt cache、原子消费和 child preflight 的实现基础，但 continuation receipt 与 replay record 必须保持不同用途和不同 key space。
- 固定推荐集合仍为 `observeScreen`、`controlBrowser`、`manageFiles`、`extractData`、`operateDesktopApp`、`composeMessage`；本轮不扩展 action kind。

## 总目标

实现一个完整但受限的可信多轮续接闭环：Gateway 只为满足严格 v0.65 安全合同的父 session 签发短时、单次、进程内 receipt 并保存有界可信父 context；用户在 iPhone/iPad/mac Mission Run 中显式生成独立 continuation draft，经新任务审批、当前 profile/参数/receipt 重验证和冻结 envelope 后按 task ID 发送；Gateway 在任何业务副作用前验证 child lineage，使用全新 workspace 执行 receipt 绑定的 selected action，再追加 `runAgentLoop` 形成真实下一轮。

## 目标

- iOS 新增独立 continuation draft 状态，不插入 `clawMobileTasks`，不改变当前 Mission task/session scope。
- 从精确父 task、父 session 和具体 AgentTrace artifact 派生 draft provenance；不得只依赖“最新一项”。
- continuation draft、child task 和两个 child actions 全部使用新 UUID；不得复用父 task/action/session ID。
- continuation task 始终重新进入手机端审批；v0.65 的 `selectedNextActionRequiresApproval=false` 不是新任务授权。
- 审批、发送、冻结 envelope 全部按明确 `taskID` 操作，发送前重新验证参数、profile、lineage、receipt 时效和审批内容摘要。
- raw frozen envelope 与 UI 展示 envelope 分离；UI、日志、artifact 和普通 event model 不得出现 raw receipt。
- Gateway 仅为 `valid contract + ready-to-continue + safe-without-approval + selected != none` 的父 session 签发 receipt。
- receipt 固定为进程内、10 分钟 TTL、全局最多 128 条、单次原子消费、Gateway 重启即失效。
- receipt record 绑定父 task/session、父 task digest、父 profile/policy/token 指纹、round、selected kind、decision contract 和有界可信父 context。
- child envelope 使用版本化结构化 lineage；Gateway 在创建 child workspace、session event、artifact 或调用 handler 前完成全部 lineage 和当前策略校验。
- child task 固定先执行 receipt 绑定的 selected action，再执行 `runAgentLoop`；第二个 action 消费 child 本轮结果并产出新的 v0.65 decision 和可选下一张 receipt。
- selected action 需要审批、最终提交、外部/破坏性 gate、证据不足、metadata gap 或其他非 safe decision 时，只生成 `needsApproval`/不可派发草稿；v0.66 禁止 continuation dispatch。
- direct、WebSocket、Swift fixture、LogicSmoke 和 XCTest 云端覆盖成功闭环、并发消费和所有 fail-closed 矩阵。

## 非目标

- 不做无人值守自动循环，不在 receipt 到达后自动创建、审批、排队或发送 child task。
- 不允许 approval-required、final-submit-review、needs-evidence、blocked、complete、policy-blocked 或 no-action decision 走 continuation dispatch。
- 不新增 Shell continuation；`runShellCommand` 不属于 v0.65 推荐集合。
- 不复用父 task 的审批状态、approval summary、envelope、task/action/session ID 或 replay authorization。
- 不把 receipt 当用户授权；receipt 只证明 Gateway 当前进程对父 decision/context 的短时绑定。
- 不跨 Gateway 进程、跨重启、跨设备或跨 10 分钟声明 continuation 有效，不实现分布式 exactly-once。
- 不复用父 workspace，不允许 child 直接读取父 `file://` reference、绝对路径或任意历史 artifact 文件。
- 不把自然语言直接交给 Shell、AppleScript 或桌面自动化；selected action 仍只消费经过校验的结构化 `toolArguments`。
- 不扩展 action/event/artifact kind，不引入第三方依赖，不实现完整 Playwright、完整 Accessibility bridge 或后台常驻服务。
- 不修改或提交用户已有的 `Claw.xcodeproj/project.pbxproj` 和 `xcuserdata` 改动。

## 信任模型与核心不变量

必须把以下三件事分开，任何一项都不能代替另一项：

1. **v0.65 decision**：证明父 `runAgentLoop` 在当时证据、request/envelope/handler 交集内推荐了哪个 action；仅 advisory。
2. **Gateway continuation receipt**：证明同一 Gateway 进程在短期内仍持有与该 decision 绑定的可信父 context；不是用户审批。
3. **child task approval**：证明用户对新的 child task、参数、lineage、当前 profile 和冻结 envelope 作了新的明确授权；不得继承父授权。

固定不变量：

- 没有完整有效 decision，不生成 receipt，不允许可派发 draft。
- 没有未过期、未消费、未淘汰且绑定完全匹配的 receipt，不创建 child workspace，不产生 session/action event，不写 artifact，不调用 handler。
- continuation receipt 必须在 child preflight 中原子 compare-and-consume；并发双提交最多一个成功，失败请求无业务副作用。
- receipt 一旦进入消费流程即不可重用；即使后续 handler 失败，也不得恢复成可消费状态。
- child task actions 必须恰好两个且顺序固定：`selectedActionKind`、`runAgentLoop`。禁止额外、缺失、交换、重复或隐藏 action。
- child `runAgentLoop` 必须由 selected action 的本轮 artifact/context 驱动；不能直接复制父 decision 充当新一轮结果。
- child 使用新 workspace。父 context 只能作为 Gateway 内存中的只读、深拷贝、限量 seed 注入，不能开放父路径。
- 任一 profile、token fingerprint、policy、allowlist、handler 或参数变化都按当前状态重新验证；父 session 当时允许不代表 child 当前允许。
- raw receipt 只允许存在于 live wire DTO、iOS 内存 receipt vault、私有 frozen envelope 和 Gateway receipt cache；所有展示、日志、event summary、artifact metadata/payload、failure summary 与测试输出必须省略或哈希化。

## 详细数据模型与 schema

### 1. iOS `ClawContinuationDraft`

新增独立、可编码测试但默认只驻留内存的模型，建议字段如下；命名可按现有项目风格调整，但语义不得缺失：

```text
id: UUID
sourceTaskID: UUID
sourceSessionID: UUID
sourceAgentTraceArtifactID: UUID
sourceSessionUpdatedAt: Date
sourceDecisionDigest: String
sourceDecisionPolicy: evidence-first-safe-v1
sourceDecisionReason: 固定 v0.65 reason
sourceSelectedActionKind: ClawMobileActionKind
sourceSelectedActionRequiresApproval: Bool
sourceRound: Int
proposedAction: ClawMobileAction
proposedLoopAction: ClawMobileAction
receiptHandle: 内存 vault key，不是 raw receipt
receiptExpiresAt: Date?
state: ClawContinuationDraftState
validationIssues: 固定枚举数组
createdAt / updatedAt: Date
```

`ClawContinuationDraftState` 至少区分：

- `readyForInput`：decision 可转草稿，但业务参数不完整；当前 v0.66 没有参数编辑 API/UI，保持阻断且不可 queue/approve/send。
- `readyForApproval`：safe decision、receipt 可用、参数完整，可显式加入任务队列。
- `needsApproval`：父 selected action 自身需要审批或 handoff 非 safe；仅展示，v0.66 不可 dispatch。
- `stale`：父 trace/session/profile/receipt 已变化、过期、淘汰或缺失。
- `queued`：已生成新 task，仍等待新审批。
- `approvedFrozen`：按内容摘要审批并冻结 raw envelope。
- `sent`：已按 task ID dispatch。
- `blocked`：固定校验失败，不可继续。

不得把 raw receipt 放进该公开模型的 `description`、UI 文本、Codable dump 或日志。实现一个私有 `ClawContinuationReceiptVault`，以随机本地 handle 映射 raw receipt；删除/过期/发送后立即清理。

### 2. child task lineage

为 `ClawMobileTask` 增加可选、版本化结构化 lineage，并由 `ClawMobileEnvelope` 正常编码。root task 为 nil；child 必须完整：

```json
{
  "contract": "claw.continuation.lineage.v1",
  "parentTaskID": "uuid",
  "parentSessionID": "uuid",
  "parentAgentTraceArtifactID": "uuid",
  "parentDecisionDigest": "sha256:<bounded hex>",
  "parentRound": 0,
  "childRound": 1,
  "selectedActionKind": "extractData",
  "decisionPolicy": "evidence-first-safe-v1",
  "decisionReason": "safe-without-approval",
  "receipt": "opaque base64url receipt"
}
```

约束：

- `childRound == parentRound + 1`；`parentRound` 限定 `0...31`、`childRound` 限定 `1...32`，超过上限 fail closed。
- `selectedActionKind` 必须是六种固定推荐 kind 且与 receipt、child 第一个 action 完全一致。
- `decisionPolicy` 必须为 `evidence-first-safe-v1`，`decisionReason` 必须为 `safe-without-approval`。
- `parentDecisionDigest` 使用固定 canonical 字段和排序生成，不包含自然语言、payload、tool arguments 或 raw receipt。
- raw receipt 不得进入 `lastClawMobileEnvelope` 的 UI 展示版本。提供 `redactedEnvelopeString`，固定显示 `"receipt":"omitted"`；transport 只使用私有 frozen raw bytes/string。
- lineage 是协议字段而不是塞入 `toolArguments` 的旁路字段。

### 3. 新任务审批记录与冻结 envelope

新增本地审批记录，至少绑定：

```text
taskID
canonicalTaskDigest
canonicalProfileDigest
lineageDigest（包含 receipt hash，不含 raw receipt）
approvedAt
```

- continuation task 始终以 `.waitingForApproval` 创建，selected action 和 loop action都不得继承父审批。
- 用户显式 `approveTask(id:)` 后才生成审批记录和该 task 的私有 frozen envelope。
- action、toolArguments、lineage、profile 安全字段、receipt 或 task 内容任一变化，审批记录和 frozen envelope 立即失效，task 回到 `.waitingForApproval`。
- `sendTask(id:)` 只发送同一 task ID 的 frozen envelope；再次 canonicalize 并比较 digest，不匹配则拒绝。
- 不允许 continuation 路径调用 `approveAndContinueAutonomousLoop()`；审批和发送必须是两个独立用户动作。

### 4. Gateway receipt wire offer

receipt 使用 Node 标准 `crypto.randomBytes(32)` 生成不可预测 base64url 值；服务端只以 SHA-256 receipt hash 为 cache key，避免原文出现在诊断。建议在父 `sessionCompleted` wire DTO 增加可选私有 `continuationOffer`：

```json
{
  "contract": "claw.continuation.receipt.v1",
  "receipt": "opaque-base64url",
  "expiresAt": "ISO-8601",
  "parentTaskID": "uuid",
  "parentSessionID": "uuid",
  "parentAgentTraceArtifactID": "uuid",
  "parentDecisionDigest": "sha256:...",
  "parentRound": 0,
  "selectedActionKind": "extractData"
}
```

- 该 offer 不是 artifact metadata，不写磁盘，不进入 event summary。
- live transport 使用私有 wire DTO 先提取 offer 存入 receipt vault，再构造不含 raw receipt 的公开 `ClawGatewayEvent` 给 reducer/UI。
- direct event API 也必须有等价提取路径；fixture/simulator 使用明确测试 receipt provider，不能生成看似真实但无法由 Gateway 验证的生产 receipt。
- 所有编码失败、未知字段或 receipt 提取失败都 fail closed；不得把 raw wire JSON写进错误日志。

### 5. Gateway receipt record 与有界父 context

Gateway 进程内 cache 最多 128 条，默认 TTL 固定 600 秒。达到容量时先清理过期记录，再按最早签发时间淘汰；淘汰后 child 固定返回不可重试错误。每条 record 至少绑定：

```text
receiptHash
issuedAt / expiresAt / consumedAt?
parentTaskID / parentSessionID / parentAgentTraceArtifactID
parentTaskDigest / parentProfileDigest / tokenFingerprint
parentRound / expectedChildRound
selectedActionKind
decisionPolicy / decisionReason / decisionDigest
requested/effective policy evidence snapshot
trustedParentContext
```

父 context 必须在 receipt 签发时深拷贝并冻结：

- 仅保留 selected handler 和后续 `runAgentLoop` 所需的固定 artifact kind 与结构化内部数据。
- 禁止保存 Authorization header、raw token、receipt、完整 envelope、自然语言原始请求、任意 `file://` reference、父 workspace 绝对路径或未限制对象引用。
- 每条 context 最多 6 个来源记录、序列化后最多 256 KiB、字符串字段逐项设上限；超限则不签发 receipt，并写脱敏固定诊断。
- receipt 成功原子消费后，把冻结 context 快照深拷贝为与父隔离的可变 child session context，再立即从全局 cache 删除原 record；child 可追加本轮结果，但不可修改父对象。
- Gateway 重启后 cache 为空，旧 receipt 固定失效；不得落盘恢复。

## receipt 签发条件

父 session 结束时，只有同时满足以下全部条件才签发：

- 父 task/session 身份一致，session 是该执行链的真实当前 session。
- 最新 AgentTrace artifact 有完整 v0.65 contract，decision digest 可稳定计算。
- `nextActionPolicy=envelope-intersection`、diagnostic `allowed`。
- `selectedActionDecisionPolicy=evidence-first-safe-v1`。
- reason 恰为 `safe-without-approval`。
- `readinessCanContinue=true`、handoff `ready-to-continue`、stopReason 为空/固定无停止语义。
- selected kind 非 `none`，审批布尔明确为 false，来自候选且 decision consistent。
- selected kind 同时属于父 request、父 envelope allowlist、固定 handler registry 和 effective intersection。
- selected kind 不是 final-submit、external、destructive 或其他当前 gate 要求审批的动作。
- 父 context 在数量和字节上限内且可安全深拷贝。

任何缺失、未知、矛盾、超限或 handler 漂移都不签发。approval-required、evidence-recovery、insufficient-evidence-fallback、policy-blocked、no-action-needed 一律无 dispatch receipt；iOS 可为非 `none` 审批型 selected action生成 `needsApproval` 草稿，但本轮不可发送。

## child envelope preflight 与执行顺序

continuation child 必须在 `validateEnvelope` 之后、task replay guard 和 `prepareSessionWorkspace` 之前进入专用 preflight。推荐顺序：

1. 做基础 schema、task ID、action kind 和 token fingerprint 校验，但不得创建 workspace/event/artifact。
2. 识别 lineage contract；root task 走旧路径，child 进入 continuation preflight。
3. 校验 lineage 所有字段类型、固定枚举、UUID、round 和 digest 格式，不回显污染值。
4. 以 receipt hash 查 cache，检查存在、未过期、未消费、未淘汰。
5. 常量时间比较 receipt/绑定摘要；核对 parent task/session/artifact、round、selected kind、decision policy/reason/digest。
6. canonicalize 当前 child profile，核对 token fingerprint、security mode、approval policy、audit policy和 receipt 绑定规则；不得用父 profile 绕过当前配置。
7. child actions 必须恰好两个且顺序为 selected + `runAgentLoop`；两个 kind 均在当前 envelope allowlist、schema 和固定 handler registry 中。
8. selected action 必须通过当前 action policy、参数 schema、workspace/external/final-submit/destructive gate；`runAgentLoop` 参数也重新验证。
9. 禁止 parent/child task ID 相同，禁止 child action ID 与父 action ID 或彼此重复。
10. 原子 compare-and-consume receipt；并发请求只有一个可成功。
11. 深拷贝 inherited parent context，删除 cache record。
12. 此后才登记 replay record、创建全新 child session/workspace、发送 `gatewayConnected` 并执行 action。

任一步失败：direct 固定返回不可重试的安全错误码；WebSocket 只允许无 action identity 的 envelope-level error event。不得创建 session workspace、replay record、action event、audit/business artifact，不得调用 handler，不得尝试网络、文件、Shell、浏览器、桌面或消息草稿副作用。错误不得回显 raw receipt、未知字段值、tool arguments、payload、路径、URL、正文或 token。

成功路径中，Gateway 保留冻结的 inherited parent context 快照，并把它深拷贝为与父隔离的可变 child `sessionContext`；child 使用全新 workspace。先执行 selected handler，将本轮 artifact 追加到 child context，再执行 `runAgentLoop`；新 AgentTrace 必须基于 inherited seed 与 child 本轮结果重新计算，不得复制父 AgentTrace。新一轮若再次满足签发条件，可为 child session 签发下一张 10 分钟单次 receipt。

## selected action 结构化参数

抽取一个共享、按 kind 校验的 continuation action builder；不得复制 `ClawMobileBridge.toolArguments` 的另一套松散 switch。六种推荐 kind 的最低合同：

- `observeScreen`：非空 `observationGoal`；`includeScreenshot`、`includeAccessibilityTree`、`includeWindowTitles`；有限 `maxCandidateControls`；固定 `redaction=maskSensitiveText`。
- `controlBrowser`：`browserGoal`、白名单浏览器 `browserApp`、`openInBrowser`，以及互斥的 `searchQuery` 或 `openURL`；搜索模板固定/白名单化；`captureTrace=true`。continuation 不得注入 placeholder `html`，不得同时提供多种冲突 URL source。
- `manageFiles`：`operation=writeText`、`workspaceOnly=true`、非空相对 `writePath`、用户复核的非空 `writeText`；缺参数时保持 `readyForInput`，Gateway 禁止默认路径/默认正文写入。
- `extractData`：`extractionGoal`、固定白名单 `sourcePriority`、有限 schema、workspace-only `outputPath`、`validateCompleteness=true`；父 evidence 只能来自 receipt 绑定的 inherited context。
- `operateDesktopApp`：明确 `targetApp`、`automationMode=accessibility`、`inputMode=typeOrPaste`、用户复核的 `draftText/pasteText`、不含 submit key 的 `keySequence`、`finalSubmitRequiresApproval=true`、`captureBeforeAfter=true`。由于该 kind 当前通常需要审批，v0.66 只生成 `needsApproval` 草稿，不 dispatch。
- `composeMessage`：结构化 `recipientOrChannel`、`deliverySurface`、用户复核的 `draftText`、`finalSubmitRequiresApproval=true`。Gateway `messageDraftAction` 必须改为只消费结构化字段，不以 `action.target/instruction` 代替业务参数；v0.66 只生成 `needsApproval` 草稿，不 dispatch。

所有参数 schema 必须有固定 key allowlist、类型/长度/枚举/互斥校验。未知 key、缺失必需 key、污染值、超长字符串、绝对/逃逸路径或冲突 alias 一律 fail closed。自然语言 objective 可以成为明确的目标字段，但不能直接成为 Shell、AppleScript、按键序列、URL、路径或最终提交指令。

## iOS 状态机与用户交互

### draft 创建

- compact Mission Run 在 Loop continuation brief 后展示 continuation draft 区域；iPad/mac Detail Dock 在 Continuation Gate 后复用同一组件和 presentation summary。
- 只有用户点击“生成下一步草稿”才调用 `prepareContinuationDraft(sourceTaskID:sourceSessionID:)`。
- 创建草稿不能修改 `clawMobileTasks`、`clawGatewaySessions`、`autonomousLoop.taskID/sessionID`、Mission scope、review focus、connection state 或 `lastGatewayLiveRequest`。
- `policy-blocked`、`no-action-needed`、`selected=none`、contract invalid 或 stale scope 不显示可创建动作，只显示固定 fail-closed 状态。
- approval 型 selected action 可生成 `needsApproval` 草稿，明确标记“v0.66 不可续接发送”；不得因用户点击草稿按钮获得 receipt 或变为 safe。

### 入队、审批、冻结与发送

```text
no draft
  -> user creates draft
readyForInput | needsApproval | readyForApproval
  -> readyForInput: blocked; future validated parameter editor required
  -> needsApproval: no queue/send transition in v0.66
  -> readyForApproval: parameters already complete
  -> user explicitly queues
queued child task / waitingForApproval
  -> user explicitly approves exact taskID
approvedFrozen
  -> user explicitly sends exact taskID
sent / observing child session
```

- `needsApproval` 在 v0.66 没有到 queued/dispatch 的转换。
- 入队时生成全新 child task 和两个全新 action ID，状态固定 `.waitingForApproval`；不得自动调用 approve/send。
- `approveTask(id:)` 与 `sendTask(id:)` 必须拒绝不存在、不是 continuation、状态不符、stale、receipt 过期或 digest 不匹配的 task。
- 用户修改 draft/task/action/profile 后，状态回到待审批，清除 approval record 和 frozen envelope。
- frozen raw envelope 由 task ID 私有保存；公开 `lastClawMobileEnvelope` 只能展示 receipt 已省略的版本。
- live transport 必须捕获并发送该 task 的 frozen envelope，不再读取可能变化的全局展示字符串。
- receipt 发送后从 iOS vault 删除；失败时也不得自动重发同一 receipt。需要用户回到父 session 获取新的可信 offer。

## 云端测试矩阵

本节定义生产合同最终必须达到的云端覆盖，不表示当前工作区 diff 已全部覆盖。当前 baseline 只有主要成功路径、receipt 复用/并发复用、单组 binding mismatch、wire offer/redaction 和一条 Swift continuation happy path；完整签发拒绝、expiry/eviction/restart、action shape/parameter/policy/side-effect、六种 kind/state/UI 与 Direct/WebSocket 对称矩阵均为残余必补覆盖。最新 `origin/main` artifact 未逐项证明前，Agent C 不得判定完整矩阵通过。

### Gateway receipt 签发

- valid + allowed + `safe-without-approval` + `ready-to-continue` + selected non-none：恰好签发一张 receipt，TTL 600 秒，绑定字段和 context 上限正确。
- approval-required、final-submit、external、destructive、needs-evidence、policy-blocked、no-action、complete、unknown/missing/contradictory metadata：不签发。
- selected 不在 request/envelope/handler effective intersection、handler registry 漂移、父 context 超 6 条或 256 KiB：不签发。
- receipt/offer 只允许出现在 WebSocket 或 `--emit-events-stream` stdout 的私有 framed wire DTO；不得出现在诊断 stdout/stderr、artifact、metadata、event summary、failure summary、JUnit、UI 可见字符串或普通 Codable event dump。

### child 成功闭环

- iOS 显式创建 draft 时父 Mission scope、task/session/event/live request 均不变。
- queue 后 child task/action IDs 全新，lineage round 正确，状态 `.waitingForApproval`，没有自动审批/发送。
- 按 task ID 审批生成匹配 digest 和 frozen raw envelope；展示 envelope 固定省略 receipt。
- 按同一 task ID 发送后 Gateway 接受 receipt，创建不同于父 session 的新 workspace/session。
- selected action 先执行并真实使用 inherited parent context；随后 `runAgentLoop` 使用 child 新结果生成新 AgentTrace。
- 成功消费后 receipt 从 iOS vault 和 Gateway cache 清理；再次提交失败且无副作用。
- 第二轮满足条件时签发不同 receipt，round 单调增加。

### child fail-closed

至少逐项覆盖：

- lineage/contract/receipt 缺失、空值、未知、污染、格式错误。
- forged receipt、错误长度、错误 hash、过期、已消费、容量淘汰、Gateway 重启失效。
- 两个并发 child 请求使用同一 receipt，最多一个成功。
- parent task/session/artifact/digest 不匹配。
- parentRound/childRound 不连续、负数、越界、溢出。
- selected kind 与 receipt、lineage、child action 不一致。
- decision policy/reason 不是固定 safe 合同。
- child task ID 复用父 ID，action ID 复用、重复或缺失。
- actions 数量不是 2、顺序错误、额外 action、缺少 `runAgentLoop`。
- token fingerprint、profile digest、security mode、approval/audit policy 不匹配。
- 当前 envelope allowlist、Gateway fixed handler、desktop/browser/workspace policy 不允许。
- selected 或 loop `toolArguments` 缺失、未知 key、alias 冲突、超长、路径逃逸或类型错误。
- receipt 校验后但 handler 失败时 receipt 仍不可重用。

每个 preflight 失败都必须断言：无 child workspace、无 replay record、无 gatewayConnected/action-bound/sessionCompleted 业务流、无 audit/business artifact、无 handler 调用、无文件/网络/Shell/浏览器/桌面/草稿副作用，错误不可重试且不回显 marker。

### Swift / presentation / state machine

- 六种推荐 kind 最终都必须覆盖正确参数草稿；不完整业务参数保持 `readyForInput`。当前 v0.66 没有参数编辑 API/UI，`readyForInput` 是不可 queue/approve/send 的阻断态，完整六种 kind 覆盖和参数编辑能力仍是残余工作。
- safe selected 可进入 `readyForApproval`；approval selected 只能 `needsApproval`，无法 queue/send。
- invalid metadata、selected none、policy blocked、no-action、stale trace、错 task/session/artifact、profile变化和 receipt 过期统一 fail closed。
- 新 draft 不改变 Mission scope；同 scope 保留 review focus，真正 queue child 后才切到 child scope，并保留安全 lineage breadcrumb。
- stale UI button 使用旧 task ID 不能审批/发送新队首任务。
- 修改 action/profile 后审批和 frozen envelope 失效；错误 task ID、摘要不匹配和重复 send 被拒绝。
- raw receipt、完整 tool arguments、URL/path、正文、token/header、父 payload、workspace 和敏感 marker 不出现在 compact/iPad UI、accessibility label、日志或 redacted envelope。
- compact 与 iPad/mac 复用同一 presentation summary，动态文本不溢出，按钮有文本、44pt 点击区域和“不自动发送”的 VoiceOver hint。

### Direct / WebSocket 对称性

- 两条路径都覆盖父 receipt 签发、child 成功、action 顺序、context 继承、新 workspace、新 AgentTrace、新 receipt、单次消费。
- 两条路径都覆盖上述 forged/expired/consumed/mismatch/policy/shape/parameter/side-effect 矩阵。
- WebSocket 失败只能产生无 action identity 的安全 envelope error；不得把未知 action kind 或 receipt 放入 Swift 闭合 enum event。
- Swift Gateway fixture `--self-test` 覆盖 private wire offer 提取、公开 event 剥离、receipt redaction、成功 child contract 和至少一组无 handler/已消费 fail-closed。

## 风险与处理

- **receipt TTL 与人工审批冲突**：用户审批超过 10 分钟必须使 draft stale，不得静默延长或复用；重新从可信父流程获取 offer。
- **并发双消费**：Node 单线程不等于自动原子；在任何 `await` 前完成同步 compare-and-consume 或使用明确临界区，测试并发双提交。
- **父 context 内存压力**：同时执行 128 条 x 256 KiB 仍有容量风险；清理过期、深拷贝上限、总量监控必须固定，测试不得下载/生成大数据。
- **receipt 在展示 envelope 泄露**：raw transport body 与 redacted UI string 必须分离，禁止沿用单一 `lastClawMobileEnvelope`。
- **latest-first race**：旧按钮、晚到事件和新任务会改变数组首项；所有 continuation 操作必须携带 task/session/draft ID。
- **审批后参数变化**：task 可变会使旧审批覆盖新行为；canonical digest 不匹配必须立即失效。
- **replay guard 顺序**：continuation lineage/receipt 必须先于 replay/workspace；否则 forged child 可能产生审计事件或占用 task replay key。
- **context 信任扩大**：只允许 receipt 签发时冻结的有限内部数据，不能把父 workspace 或 file reference 暴露给 child。
- **simulator 伪可信**：本地 simulator 不得生成可交给 live Gateway 的生产 receipt；UI 必须清楚区分测试 offer 与 live receipt，但不能显示 secret。
- **现有 handler 默认值**：manageFiles、desktop 和 compose 的 fallback 可能把缺参数变成动作；continuation 参数 validator 必须在 handler 前阻断。
