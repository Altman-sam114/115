# v0.67 / Continuation Parameter Editor（manageFiles）

提交信息：`v0.67: 补齐文件续接参数编辑`

## 版本分配依据

v0.66 已在 `origin/main` commit `bde2e7871ef7078b913ebc8cdfe4ef26af8c957f` 完成云端验收：GitHub Actions run `31290630230` attempt `1` 的 artifact `claw-ci-v0.2-main-bde2e7871ef7-run31290630230-attempt1` 已由 Agent C 复判通过。v0.66 明确保留的唯一用户可操作缺口之一是 `readyForInput`：可信父 AgentTrace 已选中 `manageFiles` 时，当前 proposal 缺少 `writeText` 会停在阻断态，但 iPhone/iPad/mac 没有结构化参数编辑入口。

本轮继续使用 v0 小版本，只补齐一个受限、可审计的文件续接编辑器，不扩展 Gateway 协议或 receipt 信任模型。

## 背景与当前架构依据

- `Claw/Core/ClawModels.swift` 已有 `ClawContinuationDraft`、`ClawContinuationDraftState`、`ClawContinuationValidationIssue`、`ClawContinuationDraftPresentationSummary` 和 `ClawContinuationContract`。
- `Claw/Services/ClawStore.swift` 的 `prepareContinuationDraft(sourceTaskID:sourceSessionID:)` 通过 `ClawContinuationActionArguments.makeAction` 生成 proposal；`manageFiles` 会从父动作复制 `writePath`，把 placeholder/缺失 `writeText` 变为空字符串，因此进入 `readyForInput`。
- `ClawContinuationActionArguments.validate` 已是 continuation action 的结构化校验边界：`operation=writeText`、`workspaceOnly=true`、非空相对路径、非空正文、允许 key 集合和 4096 字节上限。
- `queueContinuationDraft(id:)` 只接受 `readyForApproval` 且无 validation issue 的 draft；队列后必须生成全新 child task，并保持 `[selectedAction, runAgentLoop]` 顺序。
- `approveTask(id:)` 会重新校验 child、receipt、profile 和 lineage，并冻结私有 raw envelope；`sendTaskOverLiveGateway(id:)` 只发送冻结 envelope。编辑器不能绕过这些状态机。
- `Claw/Views/ContentView.swift` 的 compact Mission Run 与 regular iPad/mac Review Detail Dock 已复用 `ClawMissionRunContinuationDraftView` 和同一 `ClawMissionRunSummary.continuationDraft`，本轮继续复用这一展示入口。
- `ClawTests/ClawTests.swift`、`Tools/LogicSmoke.swift` 和 GitHub Actions 已覆盖 v0.66 continuation happy path、receipt redaction、审批、冻结和失败 transport；本轮要补 `readyForInput` 参数编辑和 fail-closed 负向覆盖。

## 目标

1. 为 `manageFiles` continuation 增加 typed 参数编辑状态/API，只允许修改：
   - `operation=writeText`
   - `workspaceOnly=true`
   - `writePath`
   - `writeText`
2. 允许用户在 draft 尚未入队时填写 workspace 相对路径和文件正文；合法输入通过既有 validator 后从 `readyForInput` 进入 `readyForApproval`。
3. 非法输入保持 `readyForInput`，返回固定、脱敏的校验提示；不得创建 child task、审批记录或 frozen envelope。
4. 编辑期间保持父 `taskID`、`sessionID`、AgentTrace artifact、decision digest、receipt handle、Mission scope 和 review focus 不变。
5. 合法输入入队后生成全新 child task/action ID，actions 恰好按 `[manageFiles, runAgentLoop]` 排列；编辑 API 对 `queued`、`approvedFrozen`、`sent`、`stale` 和 `blocked` 均拒绝。
6. compact iPhone 与 regular iPad/mac 使用同一个 summary/API/编辑视图，不显示 raw receipt、token、父 payload、Gateway 绝对路径或 metadata 内容。
7. 保持现有 Gateway handler、协议字段、receipt TTL/单次消费、lineage preflight、审批和发送流程不变。

## 非目标

- 不实现六种 continuation action 的通用编辑器；本轮只支持 `manageFiles`。
- 不修改 receipt 签发、缓存容量、TTL、消费语义、lineage contract 或 child preflight。
- 不自动 queue、approve、send、retry、refresh receipt 或跨 task 继承授权。
- 不允许绝对路径、`~`、`..`、空路径、空正文、未知 key、alias、workspace 外路径或自然语言直连 Shell。
- 不新增 Gateway action/artifact/event kind，不改变 `Tools/claw-gateway-server.mjs` 的文件写入策略。
- 不实现完整 macOS Accessibility bridge、浏览器控制器、跨进程持久化或后台 Gateway 保活。
- 不修改或提交用户已有的 `Claw.xcodeproj/project.pbxproj` 与 `xcuserdata` 改动。

## 建议实现步骤

### 1. 模型和验证边界

- 在 `Claw/Core/ClawModels.swift` 增加小型 Codable/Sendable 的文件参数编辑 summary 或等价模型；字段只表达用户可编辑值、固定 validation state 和脱敏提示。
- 不把 raw receipt、token、父 artifact reference、workspace 绝对路径或完整 envelope 放入公开 summary、日志、metadata 或普通 event。
- 继续使用 `ClawContinuationActionArguments.validate` 作为唯一结构化校验；如需补 `manageFiles` 专用验证，必须保持固定 allowed keys、相对路径规则和每个字符串值 4096 字节上限。
- 校验提示只能使用固定枚举/固定文案，例如“请输入 workspace 相对路径”“请输入文件内容”“路径必须限定在 workspace 内”“参数仍需人工复核”，不得回显危险路径或正文。

### 2. Store API 和状态机

- 在 `Claw/Services/ClawStore.swift` 增加明确的 typed API，例如 `updateContinuationFileArguments(writePath:writeText:)`；不要让 UI 直接修改 `[String: String]`。
- API 只接受当前 `continuationDraft`、且 `childTaskID == nil`、state 为 `readyForInput` 或 `readyForApproval` 的 draft；其他状态固定拒绝。
- 只允许 selected action 为 `.manageFiles`；其他 kind 维持现有 state，不被编辑 API 改写。
- 更新 proposal action 的 `toolArguments` 后重新调用 validator，清除/重建 `validationIssues`，在无 issue 且 receipt/profile/source scope 仍有效时设为 `readyForApproval`，否则保持 `readyForInput` 或 `stale`。
- 更新参数不得改变 source task/session/trace/digest/round/receipt handle/receipt expiry；不得更新 `clawMobileTasks`、approval records 或 frozen envelopes。
- queue 之前仍需重新校验 source scope、当前 profile、receipt 时效、lineage shape、action allowlist 和 loop action；入队后编辑 API 必须返回 false 或固定拒绝结果。

### 3. Mission Run summary 与 UI

- 扩展 `ClawContinuationDraftPresentationSummary`，提供 `manageFiles` 编辑器所需的有限状态、当前输入值、是否可编辑和固定校验提示；`readyForInput` 必须可见但不可 queue。
- 在 `ClawMissionRunContinuationDraftView` 中复用同一编辑器：路径使用单行 TextField，正文使用稳定高度 TextEditor，保存/应用使用明确按钮，所有交互控件至少 44pt。
- 只在 selected kind 为 `manageFiles`、draft 尚未入队且 state 为 `readyForInput`/`readyForApproval` 时显示编辑控件；按钮调用 typed Store API，不能自动 queue/approve/send。
- iPhone compact 与 iPad/mac regular 复用同一 view/summary；动态文本使用 fixedSize 或可换行布局，不展示 UUID、receipt、token、完整 Gateway path、父 payload 或 artifact 内容。
- 编辑器和按钮补充 VoiceOver label/hint，明确“只更新结构化文件参数，不会自动加入队列、审批或发送”。

### 4. 测试和文档

- `ClawTests/ClawTests.swift` 增加缺失正文、空正文、绝对路径、`..` 路径、未知 key/超长值和合法相对路径+正文测试。
- 断言非法输入不能 queue、不能创建 child task、不能生成 approval record/frozen envelope；合法输入必须得到 `readyForApproval`，且父 scope、receipt handle、lineage digest 相关字段不变。
- 断言入队后更新失败；审批后 frozen envelope 的 digest/脱敏行为不变；profile 变化、receipt 过期和父 trace 变化仍 fail closed。
- `Tools/LogicSmoke.swift` 增加不编译运行的测试源覆盖或云端 smoke 断言，覆盖编辑器状态转移、scope 保持、状态锁定和 raw secret 不外显。
- 更新 `README.md`、`Docs/claw-mobile-gateway-protocol.md`、`md/flow/flow.md`、`md/flow/flowchart.md`、`md/test/test.md` 中受影响的 continuation/readyForInput 描述，并在 `update_log.md` 记录 v0.66 云端修复验收与 v0.67 变更。
