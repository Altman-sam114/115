# v0.68 / Gateway 普通任务统一 Dispatch Preflight

提交信息：`v0.68: 增加普通任务派发前置闸门`

## 版本分配依据

v0.67 已提交到 `origin/main` commit `85eacdc2b33c629a07c7c35a4181abec360b9a5d`，GitHub Actions run `31292820330` attempt `1` 的 artifact `claw-ci-v0.2-main-85eacdc2b33c-run31292820330-attempt1` 已由 Agent C 复判通过。现有 v0.66/v0.67 continuation child 已有独立的 receipt、lineage、审批冻结和 preflight 合同，但普通任务入口仍主要依赖 envelope schema、token fingerprint 和 action allowlist；`task.status`、敏感 action 审批状态以及 dispatch 前置顺序没有统一 fail-closed 闸门。

本轮只补普通 Gateway 任务的最小派发前置检查，不扩大 action 能力、不改变 continuation 信任模型，并为 mac/iPad 后续工作保留稳定的 Gateway 合同。

## 背景与当前架构依据

- `Tools/claw-gateway-server.mjs` 的 `makeGatewayEvents` 先做基础 `validateEnvelope`，再建立 replay record；`buildGatewayEvents` 会创建 session workspace、写入 capability snapshot 和 `gatewayConnected`/artifact 事件，然后逐 action 调用 `actionPolicy`、handler 和业务 artifact。
- `actionPolicy` 当前只检查 action 是否为 `blocked` 以及是否在 envelope `allowedActionKinds` 中；普通入口没有集中检查 `task.status`、敏感 action 是否已获用户审批，也没有在 replay/workspace/event/artifact/handler 之前阻断不合法状态。
- v0.66 continuation child 必须是 `readyToSend`、`auditRequired=true`、Gateway audit/敏感审批开关开启、带有效 receipt 的全新 child；lineage/receipt 验证和单次消费合同不得被普通 preflight 取代、放宽或重复消费。
- `Tools/ClawGatewayEventFixture.swift`、`Tools/claw-gateway-direct-smoke.mjs`、`Tools/claw-gateway-smoke.mjs` 以及 Swift LogicSmoke/XCTest 是云端契约入口；普通合法 `sent` 流程已有基线，新增测试必须证明安全失败发生在任何业务副作用前。

## 目标

1. 为普通任务增加统一、可审计、fail-closed 的 dispatch preflight，并在 replay cache、session workspace、session 事件、artifact 写入和任何 handler 之前完成。
2. 普通任务仅允许既有合法发送状态 `sent` 进入正常 dispatch；`waitingForApproval`、`queued`、`blocked`、`draft`、`readyToSend`、`approvedFrozen`、`complete`、缺失/未知/异常 status 以及不满足当前审批合同的输入均固定拒绝。
3. 对 `approval != automatic` 的敏感 action，不得接受客户端仅把 task/action 标成可发送的伪造输入；必须保留 Gateway 现有敏感审批策略，失败时不执行 action、不创建 workspace/replay 业务记录、不写业务 artifact。
4. 统一错误为脱敏、不可重试、无 action identity 的 envelope-level error；错误不得回显 task ID、action ID/kind、instruction、target、toolArguments、路径、URL、正文、token、receipt 或 marker。
5. 保持合法普通 `sent` 任务的事件顺序、handler 行为和现有 policy skip/unsupported handler 合同；保持 continuation child 的 lineage/receipt/`readyToSend` 独立校验和单次消费。

## 非目标

- 不新增 action kind、artifact kind、协议字段、自然语言执行入口、后台循环、持久化 receipt、跨进程状态或真实 macOS Accessibility/browser bridge。
- 不把普通任务强制改为 continuation 的 `readyToSend`，不自动审批、冻结、queue、send、重试或重连。
- 不改变 `actionPolicy` 对已允许 action 的现有 allowlist、blocked、unsupported handler 处理；普通 preflight 只负责 dispatch 前合同，不把 handler unsupported 变成成功。
- 不修改 v0.66/v0.67 receipt TTL、缓存容量、lineage digest、child action shape、context snapshot 或公开脱敏规则。
- 不修改用户已有的 `Claw.xcodeproj/project.pbxproj`、`Claw.xcodeproj/xcuserdata/a114514.xcuserdatad/xcschemes/xcschememanagement.plist`，不混入 iPad/mac UI 重构。

## 实现步骤

### 1. Gateway preflight

- 在 `Tools/claw-gateway-server.mjs` 增加清晰的普通任务 preflight helper，或在 `validateEnvelope` 后、`taskReplayKey`/replay cache 前调用等价逻辑；必须明确区分普通任务与带 `task.lineage` 的 continuation child。
- 普通任务检查顺序固定为：schema/task/action 结构与未知 kind -> token fingerprint/基本 Gateway 合同 -> continuation 分支识别 -> task status 必须为 `sent` -> task/action approval 合同和 envelope allowlist -> 通过后才进入 replay guard、workspace、session/event、artifact、handler。
- continuation 不得走普通 `sent` 规则；保留现有 lineage shape、receipt 存在/过期/绑定/profile/policy、child status `readyToSend`、action shape、allowlist、handler 和参数 preflight 的顺序与错误语义。
- 普通 preflight 失败必须使用固定安全错误码集合，错误事件只能是无 action identity 的 envelope-level fail-closed event，`isRetryable=false`；不得为了构造错误事件而写 workspace、replay artifact 或业务 artifact。
- 注意 `task.status` 可能是客户端枚举字符串，也可能缺失/未知；未知或缺失必须拒绝，不能默认为 `sent`。只把 `sent` 视为普通首次 dispatch 的合法状态。
- 审批检查必须 fail closed：不能仅信任 `status=sent` 或 action `approval=automatic` 就绕过 Gateway 策略；保留当前 `approval`/`allowedActionKinds`/handler 合同，并确保 approval-required、destructive、final-submit 等 action 不因伪造 task status 进入 handler。

### 2. Fixture 与 Gateway smoke

- 更新 `Tools/ClawGatewayEventFixture.swift` 的 self-test，覆盖合法 `sent` 基线以及 `waitingForApproval`、`queued`、`blocked`、缺失/未知 status 和敏感 action 伪造为 automatic/已发送的失败路径。
- 更新 direct 与 WebSocket smoke，验证失败发生在 replay/workspace/event/artifact/handler 之前：workspace 无新业务文件、replay cache 不产生可执行记录、无 action event、无业务 artifact、无 Shell/网络/浏览器/桌面/文件/草稿副作用，敏感 marker/路径/正文/token 不出现在输出。
- Direct 与 WebSocket 必须对称；WebSocket 失败只能发安全 envelope error，不得带 action identity。保留合法 sent 任务、unsupported handler、后续合法 action、session completion 和 continuation child 单次消费的现有基线。

### 3. Swift 兼容与测试

- 如 `Claw/Core/ClawModels.swift`、`Claw/Services/ClawStore.swift`、`ClawTests/ClawTests.swift` 或 `Tools/LogicSmoke.swift` 需要同步固定错误/状态合同，只增加最小 fail-closed 断言；不把 Gateway 内部敏感错误码或 raw payload 暴露到 UI/event/artifact。
- XCTest/LogicSmoke 覆盖普通 sent 成功、等待审批/queued/blocked/未知 status 拒绝、approval 伪造拒绝、无敏感回显和 continuation 不回归；不得删除已有安全断言。

### 4. 文档

- 同步 `README.md`、`Docs/claw-mobile-gateway-protocol.md`、`md/flow/flow.md`、`md/flow/flowchart.md`、`md/test/test.md`：说明普通任务必须先通过 dispatch preflight，`sent` 与 continuation `readyToSend` 是两个不同合同，失败无业务副作用且以云端 artifact 为准。
- 在 `update_log.md` 追加 v0.68 版本记录、关键文件、验证结果和遗留风险；不得预写尚未产生的 CI run/artifact 为通过。

## 验收标准

1. 普通 `sent` 任务保持现有成功/事件/handler 行为；continuation child 仍仅由 receipt + lineage + `readyToSend` 合同进入。
2. 普通任务 status 缺失、未知、`waitingForApproval`、`queued`、`blocked`、`draft`、`readyToSend`、`approvedFrozen`、`complete` 均在 replay/workspace/event/artifact/handler 前拒绝。
3. approval-required/destructive/final-submit 等敏感 action 的伪造 automatic/已发送输入 fail closed；不得出现 action event、业务 artifact 或任何副作用。
4. Direct/WebSocket/fixture 失败输出不包含 action identity、task/action payload、token、receipt、路径、URL、正文或敏感 marker，且错误不可重试。
5. 合法普通 sent、现有 policy skip/unsupported handler、后续 action/session completion 和 v0.66 continuation child 单次消费没有回归。

## 风险和禁止项

- 不得把客户端 status 或 `approval=automatic` 当作唯一授权；Gateway 仍是实际执行边界。
- 不得通过先创建 workspace/replay record 再补救来声称 fail closed；状态/审批/结构 preflight 必须发生在所有业务副作用前。
- 不得把 continuation child 错误地按普通 `sent` 放行，也不得让普通任务伪造 continuation receipt/lineage 获得额外权限。
- 不得把固定错误码、task/action ID、instruction、target、toolArguments、绝对路径、URL、正文、token 或 receipt 写入普通 event、artifact、日志、JUnit、failure summary、manifest 或 UI。
- 不得删除测试断言、运行本地编译/业务 smoke、提交用户 Xcode 配置改动或混入无关 UI/协议重构。
