# v0.69 / macOS-iPad Regular Workbench Primary Action

提交信息：`v0.69: 就地化 iPad/mac 工作台主动作`

## 版本分配依据

v0.68 已在最新 `origin/main` commit `a754b4602ab044d558b8782bba25452d6e33089c` 通过云端验收：run `31295915928` attempt `1`，artifact `claw-ci-v0.2-main-a754b4602ab0-run31295915928-attempt1`，10 项检查、Direct/WebSocket smoke、LogicSmoke、fixture、Xcode build 和 XCTest 全部通过。当前产品遗留的高价值交互缺口是 regular iPad/mac 工作台右侧 Review Detail Dock 只读，Mission 的审批、继续、重试主动作仍藏在左侧长面板底部；用户在宽屏上查看证据后必须跨栏回到左栏操作。

本轮只做 regular workbench 展示与既有主动作复用，不新增 Gateway 协议或执行能力。工程没有原生 macOS target；“mac”指宽屏/regular SwiftUI 工作台在 Mac Catalyst 或 iPad 类环境中的布局语义，不能宣称已有独立 macOS 应用。

## 背景与当前架构依据

- `Claw/Views/ContentView.swift` 的 `PhoneAgentView` 按 `horizontalSizeClass` 选择 compact 或 `PhoneAgentWorkbenchLayout`；regular 布局左侧为命令与 `ClawMissionRunPanel`，右侧 `PhoneAgentReviewColumn` 包含 `ClawMissionReviewDetailDockView`。
- `ClawMissionRunPanel` 已从 `store.missionRunSummary` 读取 `primaryActionTitle`、`primaryActionIcon`、`primaryActionKind` 和 `isPrimaryActionEnabled`，并通过 `performPrimaryAction` 调用既有 Store 闸门：`startAutonomousComputerTakeover`、`approveAndContinueAutonomousLoop`、`continueAutonomousLoopAfterReview`；`waitForGateway`/`inspectBlocked` 不执行动作。
- `ClawMissionReviewDetailDockView` 已拥有同一 `ClawStore`、Mission scope、review focus、continuation draft 和 metadata-only 复核摘要，但目前没有 Mission primary action 控件。
- `ClawMissionRunSummary`/`ClawStore.missionRunSummary` 是状态的唯一展示来源；`ClawMissionRunPrimaryActionKind` 的 enabled 状态由 phase、session、retryable count 和审批闸门派生。UI 不得自行推断 phase、找 latest task 或构造 envelope。
- 当前工作区有人工未提交的 `Claw.xcodeproj/project.pbxproj` 和 `Claw.xcodeproj/xcuserdata/a114514.xcuserdatad/xcschemes/xcschememanagement.plist` 改动，包含 team/bundle/scheme 配置。任何 target family 变更必须与这些改动隔离，不能覆盖、回滚或整文件暂存。

## 目标

1. 在 regular `ClawMissionReviewDetailDockView` 中就地显示与左侧完全一致的 Mission primary action：标题、SF Symbol、enabled/disabled、tint 和 Store 行为均来自当前 `missionRunSummary`。
2. compact iPhone 保持当前单栏行为；regular iPad/宽屏工作台在 review detail 之后或稳定的顶部控制区提供主动作，避免重复执行、状态漂移或视觉跳动。
3. 抽取一个小型共享 SwiftUI 主动作组件或共享 action dispatcher，让 `ClawMissionRunPanel` 和 regular Dock 复用同一 summary/action mapping；不得复制两套 switch 后再自行维护。
4. 主动作只允许调用既有 Store API：启动、用户审批后继续、复核后重试/继续；等待 Gateway 与已阻断状态必须 disabled，不能通过 Dock 绕过审批、workspace、allowlist、live preflight、receipt、冻结 envelope 或发送闸门。
5. 所有按钮、动态标题和状态说明在 iPad/regular 宽度下不溢出、不遮挡 review 内容；控件至少 44pt，VoiceOver label/hint 明确动作不会绕过手机审批或自动发送。
6. 让 iPad target 能被工程配置覆盖：评估并将 Claw app 与 ClawTests 的 `TARGETED_DEVICE_FAMILY = 1` 最小改为 `1,2`（若当前工程/CI 约束不允许，必须在提示/提交说明中明确原因并保持代码 regular 布局可编译）。

## 非目标

- 不新增 action/artifact/event/protocol 字段，不改变 Gateway、Planner、receipt、continuation、审批、发送或任务状态机。
- 不实现原生 macOS target、Mac Catalyst target、真实 Accessibility bridge、浏览器控制器或桌面后台保活；不把 regular SwiftUI 布局描述为 macOS 原生能力。
- 不让 Dock 直接读写 `clawMobileTasks`、`lastClawMobileEnvelope`、token、raw receipt、父 payload 或 Gateway 绝对路径；不自动 queue/approve/freeze/send/retry。
- 不把 `waitForGateway`、`inspectBlocked` 显示成可执行按钮；不可执行状态必须禁用或使用明确的非动作状态视图。
- 不修改/回滚用户已有 project/user data；不混入 unrelated color/font/layout 重构，不删除已有测试断言。

## 建议实现步骤

### 1. 共享主动作控制

- 在 `Claw/Views/ContentView.swift` 提取 `ClawMissionRunPrimaryActionView` 或等价小组件，输入完整 `ClawMissionRunSummary` 和一个主动作 closure；共享标题、icon、enabled、accessibility、button style 和 disabled 状态。
- 抽取 `performPrimaryAction` 到合适的共享边界（例如 `ClawMissionRunPrimaryActionDispatcher` 不是必要时不要新增类型），确保 compact panel 与 regular Dock 调用同一 Store 方法映射。所有执行前仍以最新 `store.missionRunSummary` 和 action kind 为准，防止过期 closure 执行错误 task。
- Dock 使用当前 focus scope 与 summary，不根据 review row 的 action hint 生成第二个动作；主动作只影响当前 Mission，不改变 review focus。
- 如按钮文案需要补充等待/阻断说明，使用固定脱敏文案，不显示 UUID、payload、token、receipt、path、URL、正文或 metadata 原文。

### 2. Regular Dock 布局和无障碍

- 把 regular Dock 的主动作放在用户扫描顺序合理的位置（建议复核摘要之后、详细证据之前或 Dock 顶部），保持与右栏滚动内容间距稳定；不要把整个页面改成嵌套卡片。
- 使用稳定最小高度/可换行文本；标题长时换行而非缩小到不可读；按钮至少 44pt，VoiceOver hint 必须说明“只执行当前 Mission 的既有审批流程，不会自动发送未审批任务”。
- compact `ClawMissionRunPanel` 的现有操作语义与布局保持不变；regular 不显示两份会造成误触的可执行主按钮，若同时保留左栏按钮，左栏应改为共享组件且视觉上明确同一动作，或仅保留 regular Dock 入口但必须证明状态同步。
- Dock 的 `accessibilitySummary`/label 继续只读 metadata-only summary；主动作的 label 可读标题和状态，不读 raw task/session ID 或敏感内容。

### 3. iPad target family 的选择性变更

- 若实现 `TARGETED_DEVICE_FAMILY`，只把 app 与 test target 的配置值从 `1` 改为 `1,2`，不改变用户现有 `DEVELOPMENT_TEAM`、bundle identifier、scheme 或其他配置。
- 因 project 文件有用户未提交改动，先保存并静态核对原有 diff；提交时只能把 target-family 相关 hunk 加入 index。可使用基于 HEAD 的最小 `git apply --cached` patch 或等价选择性暂存；禁止 `git add Claw.xcodeproj/project.pbxproj` 整文件、禁止 checkout/reset、禁止覆盖 user data。
- CI 当前主要动态发现 iPhone Simulator；target family 变更应由云端 Xcode build/XCTest 覆盖，不能声称已在本地 iPad/Mac 编译验证。

### 4. 测试与文档

- `ClawTests/ClawTests.swift` 和 `Tools/LogicSmoke.swift` 至少覆盖 idle/start、waitingForApproval/approveAndContinue、needsAttention/continueAfterReview、waitForGateway disabled、blocked/inspectBlocked disabled 的 `primaryAction*` 状态不变；如新增 presentation summary/helper，覆盖 compact/regular 共享输入和 action mapping。
- 断言 Dock/共享组件使用的是当前 Mission summary scope，不从旧 task/session 或 stale review focus 触发动作；不得出现 raw receipt/token/payload/path/URL/marker。
- 如需要 SwiftUI UI preview/test，只增加最小可编译覆盖；所有 build、XCTest、LogicSmoke 和 Xcode destination 验证必须交给 GitHub Actions。
- 更新 `README.md`、`Docs/claw-mobile-gateway-protocol.md`（仅受影响的 mobile/regular UI boundary）、`md/flow/flow.md`、`md/flow/flowchart.md`、`md/test/test.md` 和 `update_log.md`，说明 regular iPad/宽屏 Dock 主动作复用既有审批状态，macOS target 仍不存在。

1. iPad/regular workbench 右侧 Review Detail Dock 能看到当前 `missionRunSummary.primaryActionTitle/icon`，并通过共享 action mapping 调用既有 Store 闸门；compact iPhone 行为不变。

## 风险与禁止项

- 不得复制一套与 `missionRunSummary` 不一致的 phase/action switch，不得从 latest task 或 review row 自行选择 task。
- 不得把 regular 布局、iPad target family 或 Mac Catalyst 语义描述成已实现原生 macOS 控制能力；真实电脑操作仍只在用户授权 Gateway。
- 不得把 UI 主按钮接到自然语言 Shell/AppleScript/桌面自动化；所有真实动作继续由结构化 Store/Gateway 闸门执行。
- 不得整文件暂存/提交用户 project.pbxproj、xcuserdata，不得回滚用户改动，不得在本地编译或以本地测试代替云端 artifact。
