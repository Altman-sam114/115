# v0.70 Agent B 实现提示词：Live Gateway 配对与安全任务恢复

## 1. 版本与本轮定位

- 版本号：`v0.70`。
- 版本分配依据：v0.69（macOS/iPad regular workbench primary action）已在最新 `origin/main` 通过 Agent C 云端 artifact 验收；Agent X 已选定 Live Gateway 配对与任务恢复作为下一轮最高价值能力。当前基线 commit 为 `23fa2b2d682dde6a821d24f60da34229a7c71eba`，不要假设本地工作区或旧 artifact 是最新基线。
- 本轮精确切片：**Pairing Diagnostics + Explicit Resume Intent Presentation**。让手机/iPad 能够清楚、脱敏地表达“本地是否已配置配对材料、Live Gateway 是否真实确认、当前任务/会话是否仍归属、是否存在可恢复意图、为什么被 replay/receipt/审批/状态边界阻断”，并让用户显式产生一次恢复意图；本轮不把意图变成后台执行器。
- 本轮交付目标是一个可在单轮实现、测试、push 和云端复判的安全切片，不是泛化的后台服务、持久调度器或完整配对协议。

## 2. 背景与当前架构依据

当前 Claw 是 iPhone/iPad SwiftUI 控制台，真正的电脑操作在用户授权的桌面 Claw Gateway。现有链路已经具备：

- `ClawGatewayProfile`：endpoint、deviceName、securityMode、短 token fingerprint、allowedActionKinds、敏感审批开关和 audit 开关。原始 token 在 Store 运行时使用，不能放入 envelope、artifact 或 UI。
- `ClawGatewayLiveRequest`：task/session affinity、脱敏 endpoint display、headers、body bytes、`canAttemptLive`、preflight message；当前 request header 会带运行时 Authorization，但任何展示和持久化摘要都必须继续脱敏。
- `ClawGatewayConnectionState`、`ClawGatewayLiveHealthSummary` 和 `ClawMissionRunLiveGatewayHealthStrip`：已表达 idle/not configured/preparing/awaiting/streaming/completed/fallback/failed、attempt/reconnect/ping、event count、fallback/error/completed 等连接健康信息。
- `URLSessionClawGatewayTransport`：WebSocket、有界重连（普通任务最多一次重试）、连接后 ping；continuation task 固定最多一次尝试，避免 receipt 对应的 frozen envelope 被自动重发。
- `ClawStore.missionRunResolution`：当前 Mission 以 task 为根，live request、session 和 events 需匹配 task/session；v0.69 dispatcher 已有 command/task/session/sessionTask/mission scope 的 stale guard。
- v0.66/v0.67 continuation：父 AgentTrace safe decision、Gateway receipt 和 child approval 是三个独立条件；receipt 只在 Gateway 进程内、TTL 600 秒、最多 128 条、单次消费；Store 有私有 receipt vault、approval record 和 frozen envelope，首次发送尝试后清理；过期、profile/policy/lineage/参数变化和 Gateway 重启都应 fail closed。
- v0.68 Dispatch Preflight：普通首次 dispatch 只允许 `task.status=sent`；continuation 独立走 `readyToSend + receipt`，失败必须在 replay/workspace/event/artifact/handler 前无副作用地拒绝。
- 当前尚无跨重启持久 secret、真实双向配对握手、后台保活或跨进程恢复协议。不要用“本地有 token fingerprint”声称 Gateway 已配对；只有实际匹配当前 task/session 的 gatewayConnected/完成事件或明确 live preflight 结果才可表达对应状态。

## 3. 本轮目标

### 3.1 配对诊断

在现有 presentation/model/store 边界内，新增一个小型、可编码/可测试的 pairing diagnostics summary（名称可依现有命名风格调整，但不要造第二套 Gateway profile）：

1. 区分固定状态：未配置 endpoint、endpoint 非 `ws/wss`、缺少运行时 token、本地 token fingerprint 已配置但尚无 Gateway 确认、当前 task 的 Gateway 已确认、当前 task 的 live transport 失败、当前 task 已回退模拟、当前 task/session 已完成、当前 task/session 不匹配或 stale。
2. pairing summary 必须同时携带安全的 task scope/session scope 结论。只有当前 Mission 的 task ID、session ID、session.taskID、`lastGatewayLiveRequest.taskID/sessionID` 和当前连接 session 归属都匹配时，才能将 Gateway ack/health 归给当前 Mission；不匹配一律显示 stale/unknown/needs re-pair，不得借用上一任务的健康状态。
3. 只展示短 token fingerprint（沿用已有 `sha256:` 短指纹）和安全 endpoint display。绝不展示 raw token、Authorization/Bearer、header map、完整 URL query、workspace、UUID、receipt、frozen envelope、父 payload 或 `toolArguments`。
4. 诊断必须告诉用户“可尝试 live”与“已真实确认”是两个不同状态；`canAttemptLive == true` 不能单独等同于 paired/connected。
5. pairing diagnostics 只从既有 profile/request/connection/session/event/continuation summary 派生，不新增生产 wire 字段，不让手机端伪造 Gateway handshake。

### 3.2 显式恢复意图

1. 为当前 Mission 派生一个 explicit resume intent presentation：`none`、`reviewBeforeResume`、`readyForExplicitResume`、`blocked` 或等价固定枚举，必须带固定 title/icon/guidance/reason，不带 raw payload。
2. 只有用户点击明确的“准备恢复/恢复前复核”入口后，Store 才能记录一个短生命周期、内存中的 intent；该动作不得打开网络、发送 envelope、审批、冻结、消费 receipt、创建 child 或自动重试。
3. intent 必须绑定渲染时的 task ID、session ID/session.taskID、mission scope、live request ID（如果存在）、profile fingerprint digest/安全 fingerprint 和当前 session revision/updatedAt 或等价版本值。Mission 切换、task/session 改变、profile endpoint/token fingerprint/allowlist 改变、session 状态改变或 continuation receipt 状态改变后，旧 intent 必须 fail closed 并显示 stale。
4. ordinary retry 只能继续走用户明确触发的既有 Store gateway send/approval 闸门；不得复用同一 task ID 静默重发以绕过 process-local replay guard。continuation 只能走现有“显式 draft -> queue -> approve/freeze -> live send”的路径，不能把 resume intent 当成 receipt，也不能由 intent 生成/刷新 receipt。
5. 若现有真正恢复 dispatch 所需的协议、服务端 handshake、跨进程 state 或新的 action/event kind 超出一轮范围，**必须停在 pairing diagnostics + explicit resume intent presentation**，不要修改 Gateway 协议；用户可以看到“需重新配对/重新运行父任务/重新生成可信 receipt”的固定提示，但不能假装恢复成功。

### 3.3 macOS / iPad 体验边界

- regular iPad/宽屏工作台右侧 Review Detail Dock 与 compact iPhone 复用同一 pairing/resume presentation summary 和同一 Store intent API；不得为 regular 布局复制一套状态机。
- 控件必须是明确的人工操作入口，最小 44pt hit target，VoiceOver hint 明确“不自动发送；需用户复核并按既有审批流程继续”。
- UI 只展示固定状态、计数、短指纹、脱敏 endpoint 和安全 guidance；不展示 UUID、URL/path/query、secret、receipt、正文、命令、浏览器内容或 artifact `file://` payload。
- 等待 Gateway、blocked、stale scope、无 token、profile mismatch、receipt 过期/已消费/未知、普通 task 非 `sent`、continuation 非 `readyToSend` 均 disabled/fail closed。

## 4. 非目标与硬禁止

本轮绝对不实现：

- 跨重启、跨进程、跨设备或分布式持久 secret / pairing key / receipt store。
- 后台无限保活、定时轮询、无界 reconnect、应用退后台继续执行、silent push、daemon 或 launch agent。
- 静默重发、自动 resume、自动 approve、自动 queue/freeze/send、receipt 自动刷新、continuation 自动重试或同 task ID 复用。
- 修改 `claw.computer.control.v1` schema、WebSocket framing、Gateway handshake、event/artifact kind、普通 dispatch preflight、replay guard 或 continuation receipt 合同。
- 让 token、Authorization header、raw receipt、父 payload、完整 toolArguments、workspace/path/URL/正文进入 envelope 公开部分、UI、VoiceOver、auditLog、artifact metadata、JUnit、failure summary、manifest 或日志。
- 把 token fingerprint、本地 endpoint 合法或 ping 成功描述成密码学配对证明；把 Gateway capability snapshot 描述成持久授权。
- 用 `ClawGatewaySimulator` 的成功结果冒充真实恢复；把 fallback simulation 当 live task recovery。
- 直接把自然语言接到 Shell、AppleScript、浏览器或桌面自动化；不放宽 allowlist、workspace、审批、敏感 action 和 handler gate。
- 原生 macOS target、Mac Catalyst target、跨设备同步、外部依赖或无关 UI 重构。

## 7. 测试要求

### 7.1 Swift/XCTest/LogicSmoke 必测矩阵

至少覆盖以下确定性场景，所有断言由云端执行：

- pairing：空 endpoint、非 ws/wss endpoint、缺 token、token fingerprint `unset`、本地 fingerprint 已有但无 Gateway ack、匹配当前 task/session 的 gatewayConnected、transport failed、fallback simulated、completed。
- affinity：Mission A 的 live request/session/health 不得出现在 Mission B；B 未发送时为空/idle 或 stale；B 发送后只接受 `request.taskID == B.task.id`、`request.sessionID == B.session.id` 且 `session.taskID == B.task.id` 的状态。
- stale intent：创建 intent 后切换 task、task-to-session、profile endpoint、token fingerprint、allowlist、session revision、continuation state；旧 intent 必须 disabled/stale，不能调用 Store send、不能改变 task/session/event/envelope/approval/frozen/receipt 状态。
- explicit intent：idle/未配置/等待 Gateway/blocked/非 retryable/普通 task 状态不允许时无意图；只有当前 live failure 或可复核的 retryable result 且 scope/身份完整时可生成 `reviewBeforeResume`/`readyForExplicitResume`。点击只记录安全 intent，不发网络、不改变 task status、不消费 receipt。
- continuation：没有 receipt、receipt 过期/已消费、draft 非 `readyForApproval`、child 非 `readyToSend`、approval/profile/lineage mismatch 时必须 blocked；有效 continuation 仍只能在既有用户审批冻结后显式 live send，intent 不得签发/刷新 receipt。
- redaction：把 raw token、`Authorization`, `Bearer`, raw receipt、UUID、`file://`, `http(s)://` query、workspace/path、正文、marker 和 `toolArguments` 注入 request/event/error/summary/UI，断言所有可见 pairing/resume 文本和审计摘要均不包含这些敏感片段；只允许安全 endpoint display、短 fingerprint、固定状态/计数。
- regular/compact parity：两种布局使用同一 summary、同一 action kind/enabled 和同一 dispatcher；按钮至少 44pt，VoiceOver hint 明确不自动发送。
- no side effect：stale/disabled/blocked explicit intent 调用前后 task/session/events/live request/envelope/approval record/frozen envelope/receipt vault 完全不变。

不要为了本轮覆盖而增加无关的六种 continuation editor、Gateway handler 或大数据 fixture；既有 v0.66/v0.67/v0.68/v0.69 矩阵必须保持回归。

## 11. 风险与禁止项清单

- 最大风险是把“配置完成”误称为“配对完成”，或把 retryable failure 误变成自动恢复。所有状态必须分离 `canAttemptLive`、`gatewayAck`、`sessionAffinity` 和 `resumeIntent`。
- 第二风险是同一 task ID 再发触发 replay guard，或 continuation receipt 在展示/重试中被错误消费。intent 只能是 UI/内存状态；真实 dispatch 必须调用既有、带 approval/lineage/receipt 校验的入口。
- 第三风险是跨 Mission 继承旧 health/session，或在 regular Dock 中绕过 v0.69 stale guard。所有 closure/dispatcher 必须带渲染时 scope 并重新核对当前 summary。
- 任何 raw token、Authorization、Bearer、receipt、UUID、完整 endpoint、workspace/path、URL、正文、toolArguments 进入可见文本、event、artifact、日志或 CI 结果都必须判定不通过。
- 任何后台 timer、无限 reconnect、跨重启 secret、协议字段扩张、自动 approve/send/retry、绕过 allowlist/workspace/审批/replay/receipt 的实现都必须退回。
- 不能删除旧测试断言、伪造成功、扩大无关范围、修改用户配置、覆盖其他 Agent 改动或把旧 artifact 当最新验收。
