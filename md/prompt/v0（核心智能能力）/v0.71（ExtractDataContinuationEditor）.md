## 本轮背景与目标

v0.66/v0.67 已建立可信 continuation 合同：父 AgentTrace 的 safe-without-approval + ready-to-continue + selected != none 才能关联短时、单次、进程内 receipt；用户必须显式生成 draft、补参数、queue、approve/freeze、send；child 使用全新 task/action/session，并严格执行 selected action 后接 runAgentLoop。v0.70 已通过，但只涉及 Live Gateway 配对诊断，不应重复修改。

当前只有 manageFiles 有 typed continuation editor。extractData 的 makeAction 已产生 extractionGoal、outputPath、schema、sourcePriority、validateCompleteness，但手机/iPad/mac presentation 和 Store 没有让用户在审批前修正提取目标或 workspace 输出文件。

本轮目标：

1. 为 extractData continuation draft 增加最小 typed editor，只允许编辑：
   - extractionGoal：非空，最多 500 UTF-8 bytes。
   - outputPath：workspace 内安全相对路径，非空，最多 500 UTF-8 bytes。
2. 固定且不可编辑：
   - sourcePriority = browserTrace,accessibilityTree,commandOutput,fileDiff,screenObservation
   - schema = title:string,source:string,summary:string,confidence:number
   - validateCompleteness = true
3. 让 Swift 客户端校验与现有 Gateway continuation preflight 对齐：exact key set、逐字段长度、安全相对路径、固定完整性策略。
4. compact iPhone 与 regular iPad/宽屏工作台复用同一 presentation summary、Store typed API 和 SwiftUI editor。
5. 保持 receipt、lineage、父 scope、用户审批、冻结 envelope、allowlist、workspace 和 Gateway 二次校验不变。

## 架构依据与实现步骤

1. 在 Claw/Core/ClawModels.swift 增加 metadata-only 的 ClawContinuationExtractionArgumentsPresentationSummary，至少有 extractionGoal、outputPath、validationMessage、isValid、isEditable、isVisible，并加入 ClawContinuationDraftPresentationSummary 及 unavailable 值。内部 scope UUID 若保留，不能由 UI/VoiceOver 显示。
2. 在 Claw/Services/ClawStore.swift 的 ClawContinuationActionArguments 中建立 extractData 固定字段的单一来源，增加 makeExtractDataArguments(extractionGoal:outputPath:)。validate(.extractData, arguments:) 必须拒绝缺失/额外字段、空值、绝对路径、~、NUL、反斜杠归一化后的逃逸、.. path segment、goal/path 超过 500 bytes、schema 超过 1000 bytes、固定字段篡改；固定 validation message 不回显输入、URL、路径、payload 或 secret。
3. 增加 updateContinuationExtractionArguments(extractionGoal:outputPath:) -> Bool。它必须只接受当前 draft、childTaskID 为空、selected kind 为 extractData、状态为 readyForInput/readyForApproval/needsApproval，并先复用 source task/session/trace/decision digest/profile/receipt 闸门。
4. safe selected draft 缺失或过期 receipt 必须 fail closed，不能刷新或伪造 receipt。approval-required draft 即使参数合法也必须保持 needsApproval、无 receipt-backed queue/send 路径、可继续编辑。
5. 非法输入保持 readyForInput，不增 task、不创建 child、approval record 或 frozen envelope，不发事件、不消费 receipt。合法 safe 输入进入 readyForApproval；合法 approval-gated 输入保持 needsApproval。只替换允许的两个 toolArguments，固定字段、父 scope、decision digest、receipt handle/expiry、source round 和 selected kind 不变。
6. queueContinuationDraft 仍是唯一创建 child 的入口，并重新校验参数、profile、allowlist、lineage 和 receipt。child actions 必须精确为 [extractData, runAgentLoop]；queue、approve/freeze、send、stale、blocked 后均锁定 editor。
7. 在 Claw/Views/ContentView.swift 的共享 ClawMissionRunContinuationDraftView 增加 extraction goal/output path 输入区。compact 和 regular 共用同一 view/API；动态文本可换行且不溢出，编辑控件和应用按钮至少 44pt，VoiceOver 明确“不自动加入队列、审批或发送”。fileArguments 与 extraction summary 互斥显示。
8. 不改变 v0.69 regular Dock 主动作、v0.70 pairing/resume intent、v0.67 manageFiles editor 的状态机。

## 风险与禁止项

- 客户端 validator 与 Node validator 可能漂移；以 Gateway 合同为上限，不能放宽 Gateway。
- extractionGoal 必须留在结构化 toolArguments，不得直连 Shell、AppleScript、桌面自动化或自然语言执行器。
- outputPath 必须同时经过客户端和 Gateway workspace 相对路径校验，不能变成任意文件访问。
- readyForApproval 不等于已审批；不得自动 queue、approve、freeze、send、retry 或刷新 receipt。
- approval-required 不能因为编辑合法而变成 safe。
- 不得把用户 goal/path、row 或正文写入 auditLog、artifact metadata、failure summary、JUnit、manifest 或普通事件；仅在用户明确审批后的私有冻结 envelope 中以结构化参数发送。
