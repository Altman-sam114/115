## 2. 背景与真实缺口

Claw 当前已经具备 Mission Run、Mac Agent readiness/policy/evidence/next-step/timeline/continuation/review/handoff 多个 metadata-only 看板，也具备：

- Mission primary action 的 stale-safe dispatcher；
- manageFiles 与 extractData 的可信 continuation draft、typed editor、queue/approval/freeze/send 闸门；
- Gateway pairing diagnostics 与只记录内存恢复意图的 explicit resume intent；
- AgentTrace 的固定候选 action、证据质量、审批需求、停止原因和 handoff 状态；
- compact iPhone 与 regular iPad/宽屏共用的 Mission Run 与 Review Detail Dock。

但现状仍有一个直接影响 Mac/iPad 工作台效率的缺口：智能体已经知道“下一步可能是审批、续接、复核、恢复意图或查看某个证据”，这些信号分散在多个板块中，用户必须在一长列看板里自行判断下一步；regular iPad/宽屏右侧也没有一个与 compact Mission Run 共享的、固定优先级的单一操作入口。现有 canContinueLoop、nextReviewAction、continuation draft 和 pairing/resume summary 不能被当成自动执行授权，必须继续经过现有人工闸门。

本轮把这些既有信号收敛为一个 Smart Operator Action Rail：它只做安全的下一步候选排序和用户显式点击分派，不引入新模型推理、不新增 Gateway action、不绕过审批。它让 Mac/iPad 更像可审计的 OpenClaw 式工作台，同时保持 iPhone 控制台与桌面 Gateway 的边界。

## 3. 本轮目标

### 3.1 目标一：固定、可测试的下一步动作选择

在现有 ClawMissionRunSummary / Store presentation 边界增加一个小型、metadata-only 的 operator action summary（名称可按现有命名风格调整），至少表达：

- 闭合的 action kind：none、primaryMission、prepareContinuation、continueContinuationDraft、prepareResumeIntent、focusReview，或等价的固定枚举；不要用任意自然语言作为 action identity。
- 固定 title、SF Symbol、status、guidance、enabled、requiresHumanAction 和安全 tone；动态 guidance 必须只由已有固定枚举/计数派生。
- 仅保留执行既有 Store API 所需的最小安全 scope/opaque binding；不得把 raw payload、完整 toolArguments、receipt、token、Authorization、workspace、URL、正文或命令带入 summary。
- Equatable/Codable/Sendable（若与当前模型风格一致），缺少输入时默认 none/disabled/fail closed。

动作选择优先级必须固定并写入测试，推荐如下：

1. 当前 continuation draft 存在可执行的既有步骤时，优先显示该 draft 的下一步：queue、approve、send 只能复用既有 draft action dispatcher；它们不会自动执行。
2. 没有 draft 但当前 continuation presentation 明确 actionKind=prepare 且 receipt/父 scope 合同有效时，显示“生成下一步草稿”，调用既有 prepareContinuationDraft。
3. 没有可执行 continuation 时，若当前 Mission primary action enabled，显示既有 primary action，并严格复用 ClawMissionRunPrimaryActionDispatcher，不能创建第二套审批/发送状态机。
4. 没有上述动作但 pairing/resume summary 明确 canPrepare 时，显示“记录恢复意图”，只调用既有 prepareExplicitResumeIntent。
5. 以上均不可执行但存在可聚焦的 nextReviewAction/priority item 时，显示“查看复核”，只改变当前 scoped review focus，不调用 Gateway。
6. 无任何安全候选、等待 Gateway、blocked、stale、scope mismatch、receipt 缺失/过期或 metadata 不足时，返回 none，显示固定阻断 guidance，不提供可点击执行入口。

优先级是本轮的产品合同。不得按字符串排序、数组偶然顺序、最近点击或 UI 出现顺序改变选择。

### 3.2 目标二：共享的 Smart Operator Action Rail

- 在 compact iPhone 的 Mission Run 与 regular iPad/宽屏的 Review Detail Dock 中显示同一个 summary、同一个 view、同一个 dispatcher；不得复制状态机。
- 在 regular Dock 中把 Rail 放在当前主要状态/健康摘要附近，确保用户不必滚动浏览所有看板才能看到下一步；在 compact Mission Run 中保持单栏可扫描，不增加重复的多个 primary/continuation 发送按钮。
- 在当前候选等于既有 primary/continuation action 时，复用既有 view/dispatcher，避免两个会做同一件事的按钮；Rail 至少提供一个清晰的“当前推荐下一步”入口或状态说明。
- 所有可点击控件最小 hit target 44pt；VoiceOver hint 必须明确该入口“不自动执行 Gateway、不自动审批、不自动发送、不自动重试；仍需用户按既有流程确认”。只聚焦复核的动作还必须明确“不改变任务状态”。
- 文本必须可换行，不得用固定宽度截断关键状态；不要引入新的大卡片嵌套、装饰性渐变或仅为占位的 UI。

### 3.3 目标三：渲染时 stale guard 与无副作用

新增 dispatcher 必须采用与 v0.69 primary action 相同的渲染快照核对策略，至少重新核对：

- action kind、title、icon、enabled；
- command、taskID、sessionID、sessionTaskID、missionScopeID；
- 当前 phase/primary action；
- continuation draft 的状态、draft/child/source scope 和 action kind（只通过现有 presentation summary 的安全值核对）；
- pairing/resume 的安全 binding digest（只比较 opaque digest，不显示）；
- 当前 focus 可用性和 review kind（若是 focusReview）。

任何渲染后任务切换、session/task 不匹配、Mission scope 变化、profile/token fingerprint/allowlist 改变、receipt/continuation 状态改变、summary 变化或 action disabled，都必须静默拒绝且无 Store 副作用。

真正的 continuation queue/approve/send 必须继续走现有 ClawStore 方法和 receipt/lineage/profile/approval/frozen-envelope 校验；真正的普通任务动作必须继续走现有 primary dispatcher。Smart Rail 不能直接调用 Gateway transport、构造 envelope、消费 receipt 或调用未经闸门的 retry 方法。

## 4. 非目标

本轮绝对不实现：

- 新的 LLM、planner、模型权重、后台自治循环或任何“自动选择后立即执行”的能力；本轮的智能仅是对既有安全 metadata 的确定性排序。
- 新 Gateway action、event/artifact kind、协议字段、WebSocket framing、handshake、pairing protocol、server state 或 Gateway handler。
- 自动 approve、自动 queue、自动 freeze、自动 send、自动 retry、receipt 刷新、后台保活、silent resume、跨重启/跨进程/跨设备状态。
- 让 Smart Rail 绕过 allowlist、workspace、审批、Dispatch Preflight、Replay Guard、continuation receipt、lineage 或 desktop policy。
- 将“可继续”“可尝试 live”“有 token fingerprint”“有 pairing summary”描述成已执行、已配对或已授权。
- 直接把自然语言接到 Shell、AppleScript、浏览器或桌面自动化；不得放宽结构化 toolArguments 约束。
- 原生 macOS target、Mac Catalyst target、外部依赖、键盘快捷键系统、跨页面导航重构或无关 UI 美化。
- 删除既有断言、降低已有安全条件、修改用户的 Xcode project/team/bundle/scheme/xcuserdata 配置。

## 8. 测试要求

所有业务测试只允许由 GitHub Actions 执行；Agent B 本地不得编译或运行 smoke。

### 8.1 Swift/XCTest/LogicSmoke 必测矩阵

至少覆盖以下确定性场景：

- idle/no task、planning、waiting approval、dispatching/observing Gateway、completed、blocked、needsAttention with retryable、needsAttention without retryable。
- 固定优先级：continuation ready action 优先于 prepare continuation；prepare continuation 优先于 enabled primary；primary 优先于 resume intent；resume intent 优先于 focus review；无候选为 none。
- continuation 的 readyForInput、needsApproval、stale、queued、approvedFrozen、sent、blocked、无 receipt、receipt expired/consumed、父 scope mismatch 均不能误报可执行 Smart Rail；可执行步骤只能调用对应既有 draft action。
- primary action 的 stale command/task/session/sessionTask/mission scope/phase/title/icon/kind/enabled 任一不匹配均拒绝，复用 v0.69 dispatcher 合同。
- resume intent 的 endpoint/profile/token fingerprint/allowlist/session revision/continuation fingerprint 变化后旧 summary disabled/stale；点击只记录 intent，不发送、不审批、不重试、不消费或刷新 receipt。
- focus review 的旧 scope、无可用 review kind、切换 task/session 后均无副作用；合法 focus 只更新绑定，不触发 Store send/queue/approve/freeze/retry。
- compact iPhone 与 regular iPad/宽屏使用同一 summary、同一 action kind、同一 title/icon/enabled 和同一 dispatcher；不要通过复制两套选择逻辑通过测试。
- Rail 的 action title、guidance、accessibility label/hint 不包含 raw token、Authorization/Bearer、receipt、UUID、file://、完整 URL/query、workspace/path、正文、命令、toolArguments 或父 payload；只允许固定状态、计数、脱敏 endpoint 和短 fingerprint（如现有安全规则允许）。
- stale/disabled/blocked/none 前后断言 task、session、events、live request、envelope、approval record、frozen envelope、receipt vault 和 Gateway connection 状态不变。
- 保持 v0.66/v0.67/v0.68/v0.69/v0.70/v0.71 既有回归断言，不删除或放宽旧安全测试。

### 8.2 SwiftUI/可用性静态合同

## 13. 风险与禁止项

- 最大风险是把“推荐下一步”误做成“自动下一步”。Rail 只产生一个用户可见候选，dispatch 必须经过既有 action/approval/receipt gate。
- 第二风险是 compact 与 regular 走了不同的选择逻辑，导致 Mac/iPad 与 iPhone 对同一 Mission 给出不同动作。必须共享 summary、view 和 dispatcher，并测试 parity。
- 第三风险是旧 summary 在任务切换、profile 变化、receipt 消费后仍可点击。必须重新核对渲染快照和 opaque binding，旧动作无副作用。
- 第四风险是把 metadata 中的 action kind、路径或正文带入 UI/accessibility/log。所有 Smart Rail 文本只能来自固定 allowlist、计数和既有脱敏值。
- 不得删除测试断言、伪造云端结果、使用非 Altman-sam114 账号、混入用户配置、覆盖其他 Agent 改动、下载大体积历史 artifact，或以旧 run/本地输出代替 Agent C 复判。
