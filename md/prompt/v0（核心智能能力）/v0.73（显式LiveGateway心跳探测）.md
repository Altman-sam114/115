## 2. 背景与真实缺口

Claw 当前已经具备：

- Live Gateway 请求 preflight、脱敏 health summary、有限重连和发送任务后的单次 ping 观测；
- v0.70 pairing diagnostics 与只记录内存恢复意图的显式 resume path；
- compact iPhone Mission Run 与 regular iPad/宽屏 Review Detail Dock 的共享展示边界；
- v0.72 Smart Operator Action Rail 的固定优先级、stale guard 和既有 Store 闸门复用。

但当前用户只能在发送电脑任务时被动获得一次 transport ping 结果。工作台没有一个可审计的、用户显式触发的“当前 Live Gateway 是否可达”探测入口；v0.70 的恢复意图明确不发网络，不能填补这个缺口。这个缺口影响 Mac/iPad 工作台在审批前判断连接准备度、在失败后区分“网络不可达”和“任务需要复核”的效率。

本轮增加一次性、用户主动触发的 Live Gateway transport heartbeat probe。它只复用已有 WebSocket 连接和安全 token header 做一次 control-frame ping/pong 观测，结果作为手机端 metadata-only 的健康复核状态展示。它不执行电脑动作、不提交 envelope、不证明 Gateway 已配对或已授权，也不替代任务发送后的真实 Gateway ack。

## 3. 本轮目标

### 3.1 目标一：有界、显式、真实的 transport probe

在现有 live health / pairing presentation 边界增加最小的 heartbeat probe summary 和 Store API（命名按现有风格调整），至少能表达固定状态：

- `unavailable`：没有当前 Mission 或没有安全的 live scope；
- `notConfigured`：endpoint 不是 `ws://`/`wss://`、token 未配置或 profile 不可尝试；
- `ready`：当前 endpoint/token/profile 满足探测前置条件，但还没有发起探测；
- `probing`：用户已显式点击，单次 probe 尚未返回；
- `transportReachable`：WebSocket 建立且一次 ping 在有界时间内成功；
- `failed` 或等价固定状态：连接、ping 或 timeout 失败，必须使用固定脱敏诊断；
- `stale`：渲染时 scope/profile/request 绑定在异步返回前发生变化，旧结果不能覆盖当前状态。

固定状态可按现有模型命名收敛，但不得用任意自然语言、原始网络错误或“已配对/已授权”作为状态 identity。summary 只允许保存固定枚举、短时刻、有限延迟/attempt 信息、脱敏错误和 opaque binding；不得保存或展示 raw token、Authorization、完整 URL/query、workspace、payload、receipt、UUID、正文、命令或 `toolArguments`。

探测必须满足：

1. 用户显式点击后才开始；没有任务、endpoint、token 或当前 profile 绑定时不得发起网络。
2. 使用已有 `ClawGatewayLiveRequest`/profile 的脱敏和 header 构造逻辑；token 只进入运行时 `Authorization` header，不进入 summary、event、artifact、日志、JUnit、manifest 或 UI。
3. WebSocket 成功打开后只发送一次 WebSocket control-frame ping，并在有界 timeout 内返回 success/failure；不得发送 JSON envelope、自然语言 instruction、action、`toolArguments` 或任何会触发 Gateway handler 的消息。
4. ping 成功只表示 transport reachable。不得把它写成 paired、authorized、Gateway ack、任务成功、审批通过、receipt 有效或真实电脑可控。
5. probe 使用独立的局部状态，不改变当前任务的 `gatewayConnectionState`、session、events、artifact、envelope、approval、frozen envelope、receipt vault、continuation state、review focus 或 Smart Rail 选择。
6. 同一 scope 的 probe 尚未结束时不得并发建立第二条探测连接；第二次点击应 disabled/ignored/coalesced，并且不能多发 ping。探测完成后只能由下一次用户点击再次探测，不得 timer、后台循环、自动重试或自动恢复。
7. WebSocket 必须在结果返回或取消后关闭，不保留后台 socket；不新增 daemon、后台保活、跨重启 cache 或持久 pairing。

### 3.2 目标二：Mac/iPad 工作台共享入口

- 在现有 `ClawMissionRunLiveGatewayHealthStripView` 或其共享子视图中就地显示 probe 状态和一个用户显式入口；compact Mission Run 与 regular iPad/宽屏 Review Detail Dock 必须复用同一 summary、view 和 Store/dispatcher，不复制两套选择逻辑。
- 入口只在 `ready`、上一次 `transportReachable` 或允许人工重新探测的 `failed` 状态可点击；`probing`、`notConfigured`、`unavailable`、`stale` 必须明确 disabled/无副作用。重新探测必须仍由用户点击，不自动执行。
- 状态文本必须可换行且保持固定布局，不新增嵌套卡片、装饰性渐变或第二套 Smart Rail。不要把 probe 混入 v0.72 的 continuation/primary/resume/focus 优先级，也不要改变 v0.72 action kind 或 dispatcher 合同。
- 可点击控件至少 44pt；VoiceOver label/hint 必须说明“只检查 Live Gateway transport，不发送任务、不执行电脑动作、不自动配对、不自动审批、不自动发送、不自动重试”。成功状态必须说明“可达不等于已授权/已配对”；失败状态只显示固定安全诊断。

### 3.3 目标三：异步 stale guard 与可审计无副作用

probe 的渲染入口或 Store API 必须绑定并重新核对当前安全 scope，至少包括：

- 当前 task/session/sessionTask/Mission scope；
- 当前 `ClawGatewayProfile` endpoint、token fingerprint、allowed action/profile digest；
- 当前 live request id/session revision（若当前架构已有）；
- continuation draft state、receipt/lineage fingerprint 和 review focus 的不透明绑定（仅在当前模型存在时比较）；
- 当前 probe generation/in-flight 状态。

调用前任何绑定不匹配必须 fail closed 且不打开 socket。异步 ping 返回后若任务、session、profile、token fingerprint、endpoint、scope、continuation 或 generation 已变化，旧结果只能丢弃或变为 stale，不能覆盖新 Mission 的 probe summary。错误路径也不能触碰任务发送/模拟回退路径。

探测结果应能让 Agent C 从云端测试证明：

- 成功有一次连接、一次 ping、一次关闭；
- 失败/timeout 不会发送 envelope 或产生 Gateway action/event/artifact；
- stale、disabled、重复点击和 profile 变化均无网络或 Store 业务副作用；
- summary、UI/accessibility、日志和测试输出没有敏感 marker。

## 4. 非目标

本轮绝对不实现：

- 新 LLM、planner、AgentTrace 推理、后台自治循环、定时器、持续 WebSocket heartbeat、后台保活、自动重连或静默恢复；
- 新 Gateway action、event/artifact kind、`claw.computer.control.v1` 字段、JSON envelope、WebSocket application message、handshake/pairing protocol 或 server-side pairing state；
- 把 WebSocket ping/pong 当作 token 验证、Gateway 配对、allowlist 通过、桌面权限、Accessibility 授权、任务 ack 或 action success；
- 自动 queue/approve/freeze/send/retry、receipt 消费/刷新、跨重启/跨进程/跨设备状态或持久 secret；
- 真实 macOS Accessibility bridge、点击/输入、浏览器控制、Shell、AppleScript、文件读写、原生 macOS target、Mac Catalyst target 或外部依赖；
- 改变 v0.72 Smart Operator Rail 的固定优先级、action kind、stale guard 或既有 continuation/primary/resume/focus dispatcher；
- 读取或展示 Gateway `file://` 内容、artifact payload、网页正文、截图、命令输出、草稿正文、联系人、完整 workspace path、raw URL/query、raw token/header、receipt、UUID 或 `toolArguments`；
- 用 probe 结果修改 `gatewayConnectionState`、任务 session、事件 reducer、artifact、模拟 fallback、approval、review focus 或任务 retry 状态。

## 8. 测试要求

所有业务测试只允许由 GitHub Actions 执行；Agent B 本地不得编译或运行 smoke。

### 8.1 Swift/XCTest/LogicSmoke 必测矩阵

至少覆盖以下确定性场景：

- 无当前 Mission、endpoint 缺失、endpoint 非 `ws/wss`、token 缺失、profile 未配置：summary 固定 unavailable/notConfigured，button disabled，fake transport 调用数为 0。
