# v0.76：AgentTrace 证据交接包

## 1. 版本与分配依据

- 版本：`v0.76`。
- 分配依据：`origin/main` 当前为 v0.75 `8adeb0b1d8d3c686c49bb4fdca513796ad9700d4`，最近一轮已完成独立 `claw.gateway.readiness.v1` control plane、严格 wire schema、stale/cancel/no-side-effect 和共享 iPhone/iPad readiness UI。本轮不重复 readiness、pairing、checkpoint、transport probe 或 Smart Operator Rail。
- 本轮主题：把现有 Gateway `agentTrace` 的证据质量、决策一致性、候选下一步和人工闸门收束成一个可扫描、可聚焦、可交接的 typed presentation summary，改善 compact iPhone Mission Run 与 regular iPad/mac Review Detail Dock。
- 提示词作者：Agent A 交付；若 Agent A 调度不可用，Agent X 依据本文件继续维护闭环，不能把本文件当作已完成实现。

## 2. 背景

当前 Gateway `runAgentLoop` 已生成 metadata-only `agentTrace`，包含 `readiness`、`satisfiedSignals`、`degradedSignals`、`missingSignals`、`selectedNextAction`、`selectedActionDecision`、`riskTags`、`stopReason`、`handoffStatus` 和 envelope intersection 结果。手机端已有 `ClawAgentTraceReviewSummary`、Loop Continuation、Evidence Coverage Map、Continuation Gate、Review Radar 和 Handoff Brief。

现有能力仍有一个交接缺口：这些组件分别表达证据、候选动作、风险和复核队列，但用户在 iPhone 或 iPad 上无法在一个固定顺序的对象中快速回答：

1. 证据是完整、降级、缺失还是 metadata 未同步；
2. 智能体选了哪一个下一步、选择是否经过固定策略和 envelope 约束；
3. 当前是否需要审批或人工复核；
4. handoff 为什么停止、是否可以由用户显式继续；
5. 这份摘要能否安全地交给下一位操作员，而不暴露原始 payload。

本轮只做 presentation-layer 的安全收束。真实电脑操作仍只在授权 Gateway 执行，手机端不读取 artifact payload，也不自动继续任务。

## 3. 目标

### 3.1 Typed handoff pack

在 `Claw/Core/ClawModels.swift` 增加独立、可测试、`Equatable`/`Codable`/`Sendable` 的 AgentTrace 交接包模型，命名应符合现有 `ClawMissionRun...Summary` 风格，例如：

- `ClawAgentTraceHandoffPackItem`：固定 `id`、`rank`、`title`、`status`、`guidance`、`icon`、tone、`reviewKind`、focus 状态、`isReady`、`requiresHumanAction`、`hasMetadataGap`、`canContinueLoop`；
- `ClawAgentTraceHandoffPackSummary`：固定标题/状态/指导、五个有限计数、selected action 的 typed title/kind、decision/handoff 的固定状态、focus 状态、`isReviewable`、`requiresHumanAction`、`hasMetadataGap`、`canContinueLoop` 和固定顺序 items；
- `ClawAgentTraceHandoffPackPresentationContract`：固定 action title/icon、最低 44pt hit area 和 VoiceOver hint。

summary 必须从现有 `ClawAgentTraceReviewSummary` 和当前 `ClawMissionRunSummary` 安全派生。建议固定五行顺序：

1. `evidence`：satisfied/degraded/missing 证据质量；
2. `decision`：selected action、candidate count/ordinal、policy/consistency；
3. `approval`：无需审批、等待审批或需人工复核；
4. `handoff`：固定 `handoffStatus` 和 stop reason 的安全本地文案；
5. `safety`：risk/metadata/policy gate 的人工边界。

所有可见文案必须通过固定 enum/allowlist 映射。不得直接显示 `handoffSummary`、instruction、objective、artifact title/reference、risk tag 原文或任何未验证字符串。selected action 只能映射现有有限 action kind title；unknown/缺失一律显示“待复核/metadata 待同步”，不能猜测为 ready。

### 3.2 Shared iPhone/iPad/mac presentation

- 在 `ClawMissionRunSummary` 上增加一个纯计算的 `agentTraceHandoffPack(focusedOn:)` 或等价 API，不重复保存一套可变状态；必须保持 task/session/review focus 归属检查。
- `ClawMissionRunPanel` 和 `ClawMissionReviewDetailDockView` 都引用同一 summary/API、同一 `ClawMissionAgentTraceHandoffPackView` 和同一 focus dispatcher。
- pack 的每一行只能聚焦 `agent-trace` 详情，不得审批、发送、重试、queue continuation、request readiness、probe、联网或调用 Gateway。
- compact iPhone 保持可纵向扫描；regular iPad/mac 可在 Dock 中完整显示五行。动态文案可换行、不得截断/覆盖相邻内容，不使用依赖屏幕宽度缩放字体。
- 所有可交互 focus 控件至少 44pt，并有明确的 label/hint：这是 metadata-only 交接复核，不会自动继续电脑动作，也不代表审批或授权。

### 3.3 Fail closed and redaction

以下任一条件时，pack 仍可显示固定的“待复核”摘要，但不得报告 ready 或允许 loop continue：

- trace 不存在、metadata 缺失或 `isRedacted == false`；
- readiness 计数/布尔值越界，satisfied/degraded/missing 出现未知 signal；
- selected action kind、decision policy/reason、candidate count/ordinal、envelope flag 组合不一致；
- handoffStatus、stopReason 或 risk metadata 未在固定 allowlist；
- task/session/mission scope 与当前 review focus 不匹配。

UI、accessibility label/hint、日志、测试摘要和 artifact 不得出现 raw command/instruction/objective、`toolArguments`、payload、artifact reference、`file://`、workspace/path、URL/query、网页正文、文件正文、stdout/stderr、截图、UUID、receipt/lineage、token、Authorization/Bearer 或 marker。只允许有限 title、count、enum title 和固定 guidance。

## 4. 非目标与禁止项

- 不新增 Gateway action、artifact、event、schema 字段、control plane、WebSocket message、handler 或真实 macOS 权限。
- 不修改 `claw.computer.control.v1`、readiness v1、v0.73 transport probe、v0.74 checkpoint、continuation receipt/lineage 或 v0.72 Smart Operator Rail 的安全合同。
- 不把 handoff pack 变成自动 planner、自动审批器、自动安全裁决器、自动 retry/reconnect、自动 queue/approve/freeze/send 或后台循环。
- 不读取 Gateway `file://` 内容或 artifact payload；不做完整 JSON viewer、网页/文件/命令查看器、截图查看器或真实 Accessibility/browser controller。
- 不让自然语言进入 Shell、AppleScript、桌面自动化或新的执行入口；所有未来动作仍须通过现有结构化 `toolArguments`、allowlist、workspace、审批和 Gateway preflight。
- 不删除/放宽既有断言，不修改用户未提交的 `project.pbxproj`、`xcuserdata`、v0.70/v0.74/v0.75 prompt，也不做无关重构。
- 不在本地执行编译、build、xcodebuild、XCTest、LogicSmoke、Gateway smoke 或 `node --check`；所有业务验证交给 GitHub Actions。

## 6. 推荐实现步骤

1. 在模型层定义严格的 handoff pack item/summary/contract；所有状态使用固定枚举或既有安全映射，未知值 fail closed。
2. 在 `ClawMissionRunSummary` 增加纯计算 projector。固定五行顺序、固定计数上限和固定 status/guidance；不要把新的可变状态放入 Store。

5. 复用现有 row/button 样式，但为新 pack 提供至少 44pt 的明确 focus hit area、换行约束和 VoiceOver label/hint。没有 Gateway action 的按钮不得使用“继续/发送/重试”等命令词。
6. 增加 XCTest 与 LogicSmoke 的正向、缺失、降级、unknown、矛盾、stale focus、redaction、compact/regular shared contract 覆盖。
7. 检查 Gateway fixture/direct/WebSocket 无需修改；若必须触碰 Gateway，必须证明只是固定 metadata regression，不能新增权限或协议，并同步相应 smoke/文档。
8. 同步 README、协议、flow、flowchart、test 和 update log，明确 v0.76 只增加本地 metadata-only handoff presentation。
9. 仅做允许的本地静态检查，提交信息使用 `v0.76: 增加 AgentTrace 证据交接包`，确认提交只含本轮文件后直接 `git push origin main`。

## 8. 测试矩阵

### 8.1 Model/projector

- idle/no trace：pack 明确 `metadata 待同步`，五行固定，不能 continue，不能 requires false-positive ready；
- 完整 `ready-to-continue` trace：证据计数、typed selected action、decision 一致性、无需审批、handoff ready、canContinueLoop 与现有 `ClawAgentTraceReviewSummary` 一致；
- waiting-for-approval/final-submit-review/blocked/complete：固定 status/guidance 正确，不能误报可继续；
- satisfied/degraded/missing 三种 evidence 组合：degraded/missing 不得计为 satisfied，metadata gap/human action 计数一致；
- unknown signal、unknown action、unknown policy/reason/status、candidate count/ordinal 越界、envelope false、decision inconsistent、风险冲突：统一 fail closed；
- redaction fixture 含 token/header/path/UUID/URL/marker/raw payload：visible pack text、accessibility text 和 serialized summary 均不得包含敏感片段；
- fixed five-row order、bounded counts、`Equatable`/Codable round trip 和 presentation contract 的 title/icon/minimum hit area/VoiceOver hint；
- stale/other task/session/focus：summary 回退到当前 scope，focus dispatcher no-op。

### 8.2 Store/UI contract

- compact Mission Run 与 regular iPad/mac Review Detail Dock 调用同一 projector、同一 view contract 和同一 focus dispatcher；
- focus 前后 task/session/events/envelope/approval/frozen/receipt/continuation/Smart Rail/readiness/checkpoint 状态完全相等；
- disabled、metadata gap、stale focus、no trace 时不调用 Gateway、不写 checkpoint、不发送、不审批、不创建 child；
- 每个可 focus 控件至少 44pt，VoiceOver 明确“只复核 AgentTrace metadata，不自动继续或执行电脑动作”；动态文本可换行且不遮挡；
- 现有 AgentTrace detail row、Evidence Coverage Map、Continuation Gate、Review Radar、Handoff Brief、v0.73 probe、v0.74 checkpoint 和 v0.75 readiness UI 回归不退化。

## 10. 风险与验收标准

主要风险是把既有 metadata 当成授权、把“可继续”误解为自动执行、或者在 iPad 宽屏重复维护一套状态。实现必须通过固定 enum、当前 scope guard、单一 projector、共享 view 和 no-op dispatcher 消除这些风险。

本轮只有在以下条件同时满足时才算 v0.76 完成：

- `origin/main` 有符合格式的 v0.76 commit，且没有混入用户保留文件；
- handoff pack 是严格 typed、metadata-only、固定五行、unknown fail closed；
- compact iPhone 和 regular iPad/mac 使用同一 summary/view/API/dispatcher，控件至少 44pt 且 VoiceOver 边界正确；
- XCTest/LogicSmoke 覆盖正向、负向、stale、redaction/no-side-effect；
- 最新 `origin/main` GitHub Actions run 通过，Agent C 已下载并核对 manifest、JUnit、摘要、主日志、关键结果文件与 commit/run/attempt 完全匹配；
- README、协议、flow、flowchart、test、update_log 均说明 v0.76 行为和非目标；
- 未新增 Gateway 权限、协议、真实 macOS 自动化、自动审批、自动继续、后台重连或敏感数据暴露。
