## 2. 背景与代码依据

当前最严重的产品问题不是缺少摘要，而是真实失败可产生模拟成功：

1. `Claw/Services/ClawStore.swift` 的 `sendTask(id:)` 在 live 模式把普通任务交给 `prepareLiveGatewayRequest(... fallbackToSimulation: true)`。缺少 token 等 preflight 失败会创建模拟结果。
2. `sendTaskOverLiveGateway(id:transport:)` 普通任务的无效 preflight 与 transport catch 都调用 `fallbackLatestSessionToSimulatedEvents`；后者把 `ClawGatewayEventStream.simulatedEvents` 写入同一个 live session。真实动作执行了一部分后断线，也可能混入假 artifact / 假成功。
3. 普通 stream 正常结束但没有 `sessionCompleted` 时未明确收口；可能一直显示 streaming。`receivedGatewayCompletion` 当前仅检查 event kind，没有先证明是本次 dispatch 的 accepted task/session terminal。
4. catch 前后对全局连接状态及 `gatewayDispatchMode = previousMode` 的恢复存在 scope 风险：任务 A 等待 transport 时，用户可以切到任务 B 或修改模式，A 的迟到结束不得覆盖 B。
5. `ClawTests/ClawTests.swift` 的 `testLiveGatewayModeFallsBackWhenTokenIsMissing`、`testLiveGatewayTransportErrorFallsBackWithHealthSummary` 明确把旧行为写成预期，`Tools/LogicSmoke.swift` 也有对应断言。必须用更严格的新合同替换，而不是删除覆盖。
6. v0.80 已防止 live session 调用模拟 retry，但没有阻止以上自动 fallback。本轮补齐该源头，保留 v0.79 普通 wire `sent`、精准审批与重复发送保护。

相关状态已有足够表达能力：`ClawGatewayConnectionState`、`ClawGatewaySessionStatus`、`sessionCompleted` 的 `.failed`、Mission/live health summary。优先沿用既有模型，不新增 Gateway wire action、artifact 或控制面。

## 3. 目标

- 用户选择 live 后，任何客户端失败均不得把任务转成模拟执行，也不得制造业务成功或 artifact。
- 明确区分“发送前配置不满足，未尝试 transport”和“已尝试发送但结果未确认/连接中断”。preflight 零调用不能声称电脑已经执行或执行失败。
- 保留已收到的真实事件、action result 与 artifact；只对本次 session 添加必要、脱敏、非业务的失败收口。
- 只有本次 task/session 的有效 Gateway terminal 才能决定完成；已确认终态不得被尾随错误、重复终态或迟到帧改写。
- 同步 live 准备入口、异步 live 入口、Mission 的调用链在同一失败合同上收口。显式模拟模式保持可用，且模拟结果来源仍清晰。
- Mac Catalyst / iPad / iPhone 复用同一个 Store 与已有 health/Mission 展示，不再把失败呈现为成功或建议模拟重试。

## 5. 实现步骤

### 5.1 先确定状态合同

1. 绘出同步 live prepare 与异步 live send 的共同路径，检查所有自动 `simulatedEvents` / fallback 调用点。
2. 显式 simulated 模式才允许生成模拟事件；普通 live 失败不再调用 `fallbackLatestSessionToSimulatedEvents`。可保留 legacy `.fallbackUsed` 的解码/展示兼容，不能为了本轮改掉历史 fixture 合同。
3. preflight 未通过时 transport 调用必须为 0。允许保留既有 request/prepared session 元数据用于诊断，但不能生成 action result、业务 artifact 或成功终态；状态/文案明确“未发送，配置待修正”。若保留 prepared session，要明确终止，不悬停运行态。
4. 不把配置失败等同已执行失败；不让未发送路径误报 Gateway ack。重复发送/重新审批仍不得绕过原来的 task guard。

### 5.2 普通 live 失败统一收口

1. 使用按精确 `taskID` / `sessionID` 查找的私有 helper 处理普通 dispatch 的 preflight、throw、无 terminal EOF 与取消，不使用 latest-first 选择目标。
2. 本地合成事件只表达客户端传输状态：可沿用 `sessionCompleted(resultStatus: .failed, isRetryable: false)`，不得带 action identity、业务 artifacts 或伪造 Gateway ack。摘要采用固定诊断代码，清楚说明结果未确认、已收到证据被保留、不会模拟执行或自动重发。
3. 错误文本不得直接插入事件/audit/Mission/checkpoint；新错误摘要使用固定枚举/代码或严格脱敏的既有 helper。不得记录 raw token、Authorization/Bearer、URL query、本机路径、toolArguments 或测试敏感 marker。不要把原始 `localizedDescription` 经另一条路径重新拼回去。
4. 部分动作已经 succeeded/failed/running 时保留其 result 和 artifacts；未知剩余动作不生成 `actionCompleted`、`actionFailed` 或成功率占位。session 为需关注，不能把“无失败业务 result”推导成完成。
5. 正常 EOF 且缺少有效 terminal，以及取消（包括 cancellation 正常结束 stream 的情况），都结束本地等待并提示结果未确认；不暗示取消已撤销远端副作用。
6. 对每个 session 只收口一次；本地合成 sequence 根据本次 session 的最大值递增，不使用其他任务的全局最大值。

### 5.3 终态与 scope 不变量

1. 先校验 wire event 的 taskID/sessionID 属于本次 dispatch，且确实能被当前 session 接受，再记录 received terminal 或消费 continuation offer。错 task/session 的 `sessionCompleted` 不能使本次执行成功，也不能误判 continuation 成功。
2. 对本次有效 terminal 进行一致处理：成功保持成功、Gateway failed 保持失败。终态后的抛错/取消/重复终态不能再追加客户端失败、模拟事件，不能覆盖真实业务结果；可以在首个有效 terminal 后结束消费。
3. 任务 A 进行中，用户排队/发送任务 B，或修改 dispatch mode / profile 后，A 的迟到错误/EOF/取消至多更新 A 自己的历史 session。不得改 B 的 task、session、live request、global connection、lastGatewayEvent、Mission、review focus 或 continuation 状态。
4. 检查当前无条件 `gatewayDispatchMode = previousMode`：不要跨 await 用旧模式覆盖用户的新选择。优先避免以临时全局模式驱动异步 dispatch；若仍需恢复，必须具有可靠的所有权/版本判断。不能只通过“当前 enum 值相同”判断用户未改动。
5. 保持 continuation 的 frozen `readyToSend`、短时单次 receipt、发送后授权失效、禁止模拟及禁止自动重连；本轮不改变其授权边界。共享终态保护不得弱化 continuation 失败状态。

### 5.5 本次复审：真实 wire 身份映射缺口

2026-10-22 只读审计确认，现有业务 diff、测试、文档和 workflow iteration 均对应本提示词；用户 signing、xcuserdata 和五份旧未跟踪 prompt 仍独立保留。已有失败矩阵可以沿用，不从头重写。Agent B 还必须补齐以下生产路径缺口：

- `URLSessionClawGatewayTransport.streamEvents` 当前仅检查远端 event 的 taskID，然后把任意远端 sessionID 重写成本地 prepared sessionID。Store 的 wrong-session fake 测试绕过这个映射，不能证明真实 wire 流的 session 身份可信；同一 task 的不同远端 session terminal 可被归一化成当前 session。
- 本次 socket 首个接受的合法业务 event 绑定远端 sessionID；后续业务 event 必须匹配同一 task 与远端 session，再映射成本地 session。绑定必须属于本次 transport/socket，不与其他并发任务共用；收到任何已接受业务事件后仍不得自动重发 envelope。非法身份只能固定脱敏失败，不能先 yield 到 Store 或 capture offer。
- 本地 prepared sessionID 与 Gateway 新建的远端 sessionID 本就可以不同，不能直接要求二者相等。continuation offer 仍按原始 wire event 的 parentTaskID/parentSessionID 校验，并保留真实远端 parentSessionID 给 child lineage，不能为了通过测试写成本地 UUID。
- 可以提炼小型纯身份/归一化 helper，让真实 transport 与云端 XCTest/LogicSmoke 共用。覆盖合法远端到本地映射、同 task 切换远端 session、错 task、错误 offer parent session、合法 remote parent 与 local session 不同；拒绝路径无错误 terminal/业务 artifact/receipt 入库，已接受 partial evidence 保持。Gateway 正常 `sessionCompleted` 可以没有 resultStatus，维持已有协议兼容，不扩大为 schema 改造。
- 当前 XCTest 的 hold recorder 已有 5 秒 fail-safe；保留有界释放和取消，不加入本机网络测试或本地运行。编译正确性、上述新回归及完整平台矩阵均由新 main artifact 验收。

## 7. 云端测试矩阵

所有 fake 有界、可取消，不用 sleep 猜时序、不挂起无界 continuation；禁止在 `XCTAssert`/`expect` autoclosure 中直接 await，先取结果再断言。

1. **未审批与重复发送**：未审批零 transport、零 session；已发任务不能再次审批/发送，v0.79 不退化。
2. **preflight**：空 endpoint、非 ws/wss、缺 token；同步与 async live 入口均无 fallback、无业务 result/artifact/成功终态，async transport 0 call；summary 说明未发送，无 ack，不能成为 completed。
3. **立即抛错**：fake transport 恰好 1 call 后 throw，session 明确失败/需关注，零业务结果、零 simulated/fallback；不得出现 raw 敏感错误。
4. **部分执行后断线**：fake 给出匹配的 actionCompleted + artifact、另一个 actionStarted，再 throw。先前 result/artifact 深度相等保留；未完成动作不被模拟填成功；只有一次本地 session 失败收口。
5. **无 terminal EOF**：空 stream 和 partial stream 正常 finish 均不能维持 streaming 或成为 completed；仍无伪业务事件。
6. **取消**：通过真实 `Task.cancel()` 和有界 recorder 测试等待时取消，以及部分结果后取消；确认等待结束、不会重发、不会模拟、文案不承诺撤销远端执行。
7. **terminal 后尾随错误**：匹配成功 terminal 后 error 保留完成；匹配 failed terminal 后 error 保留失败，均不追加模拟结果或第二次收口；重复 terminal 不可改写结果。
8. **身份门禁**：错 taskID、错 sessionID 的 terminal 不能算完成；也不能修改其他 session 或提供有效 continuation completion/offer。随后 EOF/throw 按本次未确认收口。
9. **任务交错**：A 在等待，用户建立 B（至少覆盖 B 未发送与 B 已发送两种）；释放 A 的迟到 error/EOF，B 的任务、session、request、connection、lastGatewayEvent、Mission、focus 快照不变，A 的历史证据保留。
10. **模式变更**：A await 期间用户切换 live/simulated 或建立 B；A 返回不得无条件恢复旧 `gatewayDispatchMode`。包括切换后再切回相同 enum 的情形，防止值比较掩盖旧所有权。
11. **显式模拟与 retry 隔离**：新鲜模拟任务仍按原样运行、模拟 retry 有效；live 失败即使用户切换模式也不能进入 simulator retry，且事件/artifact/approval 不变。
12. **健康与 Mission**：live throw/EOF/cancel 不出现 false completed 或 fallback；preflight 未发送无 Gateway ack；Mac/iPad/compact 读取同一真实状态；probe/readiness/checkpoint、continuation 和 v0.79/v0.80 回归保留。

XCTest 负责完整 async/fake/交错矩阵；LogicSmoke 至少覆盖同步 preflight 不回退、普通失败/部分结果或等价纯 projector、显式模拟正常与重复派发保护，并保持既有全部断言。将旧“失败应 fallback 成功”断言改成新 fail-closed 合同，同时保留或加强脱敏、task 身份与副作用断言；不得简单删除测试。
